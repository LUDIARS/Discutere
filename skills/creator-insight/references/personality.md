# 性格（行動スタイル）

ビッグファイブの枠を借りるが、出力は特性の点数ではなく、観測できた行動スタイルの記述にする。
文章や行動ログからの性格推定は、研究でも中程度の当たり方にとどまる。個人を断定する精度は無い。

## 扱う範囲

| 特性 | 扱い |
|---|---|
| 外向性 | ログから記述する |
| 協調性 | ログから記述する |
| 勤勉性 | ログとコードから記述する |
| 開放性 | ログとポートフォリオから記述する |
| 神経症傾向（情緒の安定） | **扱わない。** 心身の状態の推定に近づくため、ログからも設問からも出さない |

## 指標

すべてロジックで数える。指標の定義は `tools.md` の特徴量の表。

### 外向性

- 自分から話を始める率（`initiation_rate`）
- やりとりする相手の広さ（`partner_breadth`）
- 公開チャンネルでの投稿の割合（`public_share`）

読み違えやすい点: リーダーや広報の役割で増える。読むだけ、リアクションだけの参加は普通にある。
個別メッセージ中心の人は公開ログに出ない。

### 協調性

- 他人の質問に答える率（`help_giving_rate`）
- 感謝・了解の表明（`ack_rate`）、リアクションを付ける数（`reaction_given_per_week`）
- 異論を出す頻度（`disagreement_rate`）と、和らげた言い方の割合（`softened_disagreement_share`）

読み違えやすい点: 敬語とクッション言葉は礼儀であり、協調性ではない。
異論の少なさは、協調性ではなく場の圧力の反映かもしれない。

### 勤勉性

- 報告の率（`report_rate`）、期限に触れたあとに完了報告が続く割合（`deadline_followup_rate`）
- コミットの規則性（`commit_regularity`）、直後の小修正の割合（`fixup_share`）、テストに触れる割合（`test_touch_share`）
- 放置されたPRの割合（`pr_abandoned_share`）、ポートフォリオの完成作の割合（`completed_share`）

読み違えやすい点: チームの規約、CI、AIコーディング支援で大きく変わる。兼務や担当替えの時期は下がる。

### 開放性

- 話題の広さ（`topic_breadth`）、外部リンクの共有（`link_share_rate`）
- ポートフォリオのジャンルの広さ（`genre_breadth`）

読み違えやすい点: 担当範囲が狭いと低く出る。広さと深さは別で、同じ主題を掘り続ける人は低く出る。

## コードを読むときの注意

- コード本体の書き方（命名、整形、コメント）は、リンタ・規約・AI支援の影響が大きい。性格の根拠にしない。
- 本人の判断が出る所を見る。コミットの切り方、PRの説明文、レビューでのやりとり、何にテストを書くか、何を後回しにするか。
- 生成物、vendor、自動整形だけのコミットは除く。AI支援の共同作成者表記があるコミットは別に数える（`ai_coauthored_share`）。

## ポートフォリオを読むときの注意

ポートフォリオは「見せたい自分」を編集したもの。性格より、価値観と動機の手がかりになる。

- 最初に何を置いているか（技術 / 見た目 / 物語 / 遊びの手触り / 数字の成果 / チームでの役割）
- 説明文の主語（自分 / チーム）、失敗や学びに触れているか
- 完成作と試作の割合、同じ主題の繰り返しの有無

## 出し方

- 集団内の相対位置（z値）を「低め / 中ほど / 高め」で書く。境は −0.5 と +0.5。
- 集団が8人未満なら相対位置を書かず、本人の中での記述にとどめる。
- 特性ごとに、根拠の指標、確度、読み違えの可能性を1行ずつ添える。
- 指標が2つ以上そろわない特性は「データ不足」とする。
- 自己申告の尺度（組織が利用許諾を持つ既存の日本語版尺度）の結果があれば並べ、ログとの食い違いを書く。
  食い違いは「場での役割」と「本人の実感」の差であることが多い。尺度の設問はこのスキルに含めない。

## 最低限のデータ

| ソース | 目安 |
|---|---|
| チャット | 200投稿以上、4週間以上、2チャンネル以上 |
| コード | 30コミット以上、4週間以上 |
| ポートフォリオ | 2作品以上 |

満たないソースは使わず、「データ不足」と書く。
