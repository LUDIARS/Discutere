# 人生脚本（アンケート式）

人生脚本は交流分析（TA）の概念で、幼い頃に作られ、その後の節目で繰り返される行動の筋書きを指す。
理論としての実証は強くない。ここでは「本人が自分の繰り返しパターンに気づくための枠組み」として使い、
結果を性格や能力の判定として扱わない。

ログから脚本を推定しない。**本人が答えるアンケートを正とし**、ログは答えと照らす材料にだけ使う。

## 測るもの

| 軸 | 内容 | 設問 |
|---|---|---|
| ドライバー | 「こうしていれば大丈夫」という5つの駆り立て | 5種 × 4問 + 強制選択5問 |
| プロセス脚本 | 時間の使い方に出る6つの筋書き | 6種 × 3問 |
| 基本的構え | 制作・チームの場面での、自分と他者への構え | 2軸 × 4問 |

禁止令（「存在するな」など）は扱わない。幼少期と家族に踏み込み、対話の場で安全に扱えないため。

設問と採点キーは `data/life-script-questionnaire.ja.json`。51問、所要10分ほど。
設問は制作・学習・チーム活動の場面に限って書いてある。既存の検査（TEGなど）の設問は使っていない。

## 実施

- 4件法（あてはまらない / あまりあてはまらない / ややあてはまる / あてはまる）。中間の選択肢は置かない。
- セクションの中で設問をシャッフルして出す（同じ尺度の設問を並べない）。シードは固定する。
- 冒頭に「正解はない」「評価に使わない」「答えたくない設問は飛ばしてよい」と示す。
- 本人が自分で答える。他人が本人について答える形では使わない。

## 採点

すべてロジックで行う。LLMを使わない。

1. 逆転項目（`reverse: true`）は `5 - 回答` に直す。
2. 尺度得点 = 回答済み項目の平均（1〜4）。回答が項目数の75%に満たない尺度は「未回答」とする。
3. 本人平均 = 同じ軸の尺度得点の平均。ドライバーなら5つの平均。
4. **優位** = 尺度得点が3.0以上、かつ本人平均より0.5以上高い尺度。上位2つまで。該当なしなら「明確な優位なし」と書く。
5. 強制選択 = 尺度ごとの選択回数（0〜5）。優位の尺度が2回以上選ばれていれば確度「高」。選ばれていなければ確度「中」とし、食い違いをメモに書く。
6. 基本的構え = 自己・他者それぞれの平均。2.5を境に4象限。2.25〜2.75は「境界」とし、どちらとも書かない。

回答の偏りを検査する。検査には逆転前の回答をそのまま使う。標準偏差は回答数で割る（母標準偏差）。

| 検査 | 条件 | 扱い |
|---|---|---|
| 一方向 | 全評定の平均が3.5以上、または1.5以下 | 絶対値を書かず、相対順位だけ書く |
| 平坦 | 全評定の標準偏差が0.4未満 | 「差が出ていない」と書き、優位を出さない |
| 逆転の矛盾 | 逆転項目（変換後）と、同じ尺度のほかの項目の平均との差が2.0以上 | その尺度の確度を「低」にする |

閾値は初期値で、根拠となる基準集団はまだ無い。回答が30件たまったら分布を見て見直す。
見直すまでは「本人の中での相対」以外の読み方をしない。

採点の検算用に、架空の回答 `examples/life-script-answers.example.json` と、
その採点結果を含む `examples/feature-card.example.json` を置いてある。採点ツールを作るときの受入テストに使う。

## 読み方

### ドライバー

| ドライバー | 日本の現場でよくある現れ方 | 対話で確かめること |
|---|---|---|
| 完全であれ | 「ちゃんとしてから出す」。途中のものを見せない。細部の直しが続く | どこまで出来たら人に見せてよいと思うか |
| 強くあれ | 我慢する。弱音を吐かない。相談が遅れる | 最後に人に助けを求めたのはいつか |
| 努力せよ | 頑張っていること自体で安心する。手を広げ、仕上がらない | 「楽に終わった」仕事をどう感じるか |
| 喜ばせよ | 空気を読む。断れない。迷惑をかけることを強く避ける | 断りたかったのに引き受けたものは何か |
| 急げ | すぐ返信する。待てない。詰め込む | 急がなくてよい場面でも急いでいないか |

ドライバーは強みの裏返しでもある（丁寧さ、粘り強さ、行動量、気配り、速さ）。メモには両面を書く。

### プロセス脚本

| 脚本 | 筋書き | 制作での現れ方 |
|---|---|---|
| 〜までは | 終わるまで楽しんではいけない | 楽しみの後回し。休めない |
| 〜の後は | 良いことの後には悪いことが来る | 好評の直後に不安が強まる |
| 決して | いちばん欲しいものは手に入らない | 構想だけで着手しない |
| いつも | なぜいつもこうなるのか | 環境を変えても同じ問題を繰り返す |
| もう少しで | あと少しのところで届かない | 完成直前で止まる。達成しても実感がない |
| 結末なし | 区切りの先が白紙 | リリースや卒業の後の計画が無い |

TAの理論では、ドライバーとプロセス脚本に対応があるとされる
（完全であれ↔〜までは、強くあれ↔決して、努力せよ↔いつも、喜ばせよ↔〜の後は）。
採点には使わない。両者が対応していれば確度を1段上げ、対応していなければ対話の問いにする。
プロセス脚本には強制選択が無いので、もとの確度は「中」とする。

### 基本的構え

制作・チームの場面に限った自己評定であり、人としての価値の判定ではない。
メモでの書き方を象限ごとに決めておく。

| 自己 | 他者 | メモでの書き方 |
|---|---|---|
| 肯定 | 肯定 | 自分にも周囲にも期待を持って動けている |
| 肯定 | 否定 | 自分でやったほうが確実と感じやすい。任せにくさについて聞く |
| 否定 | 肯定 | 周囲を高く見て、自分の出来を低く見積もりやすい。謙遜の習慣と区別して聞く |
| 否定 | 否定 | 象限の名前を書かない。「いまの環境で、自分にも周囲にも期待を持ちにくい時期かもしれない」とだけ書き、状況について聞く |

自己が「否定」に寄った結果は、控えめな自己評定の習慣でも出る。単独では意味づけしない。

## ログとの照合

任意。話のタネにだけ使う。
アンケートの優位と、特徴カードの行動指標が合うか、食い違うかを見る。
食い違いは誤りではなく、対話の入口である。

| アンケート | 見る行動指標 |
|---|---|
| 完全であれ | 自分の投稿の編集率、直後の小修正コミット、途中経過の共有の少なさ |
| 強くあれ | 質問・相談の率の低さ |
| 努力せよ | 着手の多さに対する完了報告の少なさ、未完の試作の割合 |
| 喜ばせよ | 異論の表明の少なさ、感謝・リアクションの多さ |
| 急げ | 返信までの時間の短さ |
| もう少しで | マージされずに閉じたPR、公開直前で止まった作品 |
| 決して | 企画・構想の投稿の多さに対する着手の少なさ |

行動指標だけから脚本を言わない。アンケートが無い場合、この分析は「未実施」と書く。

## やらないこと

- 禁止令・幼少期・家族関係を尋ねる、推測する。
- 「敗者の脚本」のような勝敗のラベルを付ける。
- 結果を固定的な性質として書く。脚本は気づけば書き換えられる、というのがこの枠組みの立場である。
- 強い落ち込みや不調が語られたのに分析を続ける。その場合は分析を止め、信頼できる人や専門の窓口に話すことを勧める。
