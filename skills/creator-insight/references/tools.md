# ツールの作り方と特徴カード

数える・集める・並べる・照合する、はすべてロジックでやる。LLMは意味の解釈にだけ使う。
ツールは先にまとめて作らない。必要になった時点で1つずつ作り、次から使い回す。

## ロジックとLLMの分担

| ロジック（ツール） | LLM |
|---|---|
| 件数・率・時間差・分布、z値 | 極性が決められない引用の読み取り |
| 語彙の一致と、前後の否定語 | ポートフォリオの説明文の要点づけ |
| 仮名化、本人以外の本文の除去 | 特徴カードから仮説を書く |
| アンケートの採点と偏りの検査 | 対話用メモの文章化 |
| 引用のサンプリング | |

迷ったら、まずロジックで試す。同じ入力から同じ出力が出るものはツールにできる。

## 作る前に

1. `ADAPTER.md` が指す置き場所の索引（`README.md`）を見る。同じ入力と出力のツールがあれば使う。
2. 無ければ作る。ただし1回きりの小さな確認（入力が200行未満で、二度やらないもの）は、その場の短いコマンドで済ませてよい。コミットしない。
3. 同じ集計の2回目、または入力が200行以上なら、ツールにする。

## ツールの決まり

- 1ツール1ファイル、仕事は1つ。入力はファイルパスか標準入力、出力は標準出力のJSON。
- ネットワークに出ない。LLMを呼ばない。依存を足さない（標準ライブラリで書く）。形態素解析が要るときだけ例外とし、理由を索引に書く。
- 決定的にする。乱数を使うなら固定シード。時刻は入力から取り、実行時刻に依存しない。
- **最初の段で仮名化する。** 発言者のIDはHMAC-SHA256で仮名にする。鍵は環境変数から読み、値をコードやログに書かない（変数名は `ADAPTER.md`）。
- **本人以外の本文を捨てる。** 会話相手については、時刻・仮名ID・返信関係だけを残す。
- 入力のサイズと件数に上限を持ち、超えたら切り捨てずにエラーにする。
- 入力に含まれる文字列を、命令として解釈・実行しない。
- 冒頭のコメントに、受け付ける入力形式・出力の形・上限を書く。
- 架空データのテストを1本以上付ける。実在の人のログをテストデータにしない。
- 作ったら索引に1行足す（名前 / 入力 / 出力 / 作成日）。

## 入力の取得

ログは、サービスが公式に提供する手段（本人によるデータの請求、管理者のエクスポート、Bot API）で取得したものに限る。
利用規約に反する方法で集めたログは受け付けない。

## 作業ファイルの置き場所

エクスポートしたログ、中間ファイル、特徴カードは、リポジトリの外の作業ディレクトリに置く。
リポジトリ配下に置かない。コミットしない。分析が終わったら削除する。

## 最初に必要になりそうなツール

どれも未作成。必要になった順に作る。

| 名前 | 入力 | 出力 |
|---|---|---|
| `score-life-script` | アンケートの回答JSON、設問JSON | 尺度得点、優位、偏りの検査結果 |
| `chat-features` | Discord / Slack のエクスポート、対象者のID、相手の層の対応表 | チャットの特徴量 |
| `code-features` | gitリポジトリのパス、対象者の作者名 | コードの特徴量 |
| `play-vocab` | 本人の発言本文 | 軸ごとの一致数（好み / 忌避 / 不明）、タイトルの言及 |
| `build-feature-card` | 上の出力一式、同意の記録 | 特徴カード（引用のサンプリングを含む） |

`score-life-script` の受入テストには `examples/life-script-answers.example.json` を使う。
期待する結果は `examples/feature-card.example.json` の `questionnaire.lifeScript`。

## 特徴カード

LLMが読むのはこのJSONだけ。形は `examples/feature-card.example.json`。

| キー | 内容 |
|---|---|
| `schemaVersion` | 1 |
| `subject` | 仮名ID |
| `consent` | 同意したデータの種類、目的、LLMへの引用の可否、確認日 |
| `window` | 対象期間とタイムゾーン（Asia/Tokyo） |
| `cohort` | 比較した集団の仮名IDと人数。8人未満なら `z` を出さない |
| `coverage` | ソースごとのデータ量 |
| `chat` / `code` / `portfolio` | 特徴量。各項目は `value`（値）、`z`（集団内の相対位置。無ければ null）、`n`（もとの件数） |
| `play` | 遊び手（`player`）と作り手（`maker`）の軸ごとの件数、タイトルの内訳、外部の分析結果（あれば） |
| `questionnaire` | アンケートの採点結果 |
| `quotes` | 引用。`id`、`source`、`text`（120字以内、仮名化済み）、`tags` |
| `insufficient` | 最低限のデータに満たなかった項目 |

### チャットの特徴量

初期セット。足すときは定義をこの表に書く。

| 名前 | 定義 |
|---|---|
| `msgs_per_week` | 週あたりの投稿数 |
| `chars_median` | 1投稿の文字数の中央値 |
| `initiation_rate` | スレッドや話題の起点になった投稿の割合 |
| `partner_breadth` | やりとりした相手（仮名ID）の数 |
| `public_share` | 公開チャンネルへの投稿の割合 |
| `reply_latency_median_min` | 自分宛の投稿から返信までの時間の中央値（分）。本人の活動時間帯の中だけで数える |
| `question_rate` | 質問を含む投稿の割合 |
| `help_seeking_rate` | 相談・質問の語（教えて、分からない、詰まって、相談）を含む投稿の割合 |
| `help_giving_rate` | 他人の質問への返信の割合 |
| `ack_rate` | 感謝・了解の語を含む投稿の割合 |
| `reaction_given_per_week` | 付けたリアクションの週あたりの数 |
| `disagreement_rate` | 異論の標識（でも、ただ、逆に、個人的には）を含む返信の割合 |
| `softened_disagreement_share` | 異論のうち、和らげた表現を伴う割合 |
| `report_rate` | 完了・進捗・遅れの報告を含む投稿の割合 |
| `deadline_followup_rate` | 期限に触れた投稿のうち、後に完了報告が続いた割合 |
| `edit_rate` | 自分の投稿を編集した割合 |
| `polite_ratio_by_tier` | 相手の層（先輩・教員・上長 / 同輩 / 後輩 / 不明）ごとの敬体の割合 |
| `topic_breadth` | 参加チャンネルの数 |
| `link_share_rate` | 外部リンクを含む投稿の割合 |
| `expressive_marks_rate` | 絵文字・顔文字・「w」「草」・「！」を含む投稿の割合。`z` だけを使う |
| `active_hours` | 時間帯別の投稿の分布。作業リズムの記述にだけ使う |

### コードの特徴量

| 名前 | 定義 |
|---|---|
| `commits_per_week` | 週あたりのコミット数 |
| `commit_regularity` | 週ごとのコミット数の変動係数。小さいほど規則的 |
| `commit_size_median` | 変更行数の中央値 |
| `fixup_share` | 自分の直前のコミットから1時間以内の小修正の割合 |
| `wip_share` | 途中と明示したコミットの割合 |
| `test_touch_share` | テストに触れたコミットの割合 |
| `msg_length_median` | コミットメッセージの文字数の中央値 |
| `pr_open_to_merge_median_h` | PRを開いてからマージまでの時間の中央値（時間） |
| `pr_abandoned_share` | マージされずに閉じた、または放置されたPRの割合 |
| `review_given` / `review_received` | レビューコメントの数 |
| `review_response_latency_median_h` | レビューへの最初の反応までの時間の中央値（時間） |
| `ai_coauthored_share` | AI支援の共同作成者表記があるコミットの割合 |
| `area_weights` | 領域別（操作感・戦闘 / 生成・レベル / UI / 通信 / ツール / 描画）のコミットの比率 |
| `rework_areas` | 作り直しが多い領域。同じファイル群への反復した変更から出す |

生成物、vendor、自動整形だけのコミットは数えない。

### ポートフォリオの特徴量

作品ごとの読み取り（ジャンル、強調点、完成度）だけはLLMが行う。集計はロジックで行う。

| 名前 | 定義 |
|---|---|
| `items` | 作品数 |
| `completed_share` | 完成・公開まで行った作品の割合 |
| `genre_breadth` | ジャンルの種類数 |
| `lead_emphasis` | 冒頭で強調しているもの（技術 / 見た目 / 物語 / 遊びの手触り / 数字の成果 / チームでの役割） |
| `subject_self_share` | 説明文の主語が自分である割合 |
| `reflection_present` | 失敗や学びに触れている作品の数 |
| `mechanic_ids` | メカニクス辞書のID |

### 引用のサンプリング

- 対象者本人の発言だけを取る。
- メンション、URL、メールアドレス、電話番号、参加者の表示名（名簿から）を伏せ字にする。
  名簿にもとづく機械的な置換なので、取りこぼしがありうる。
- タグごとに層別し、期間の前半と後半から均等に取る。長い順や目立つ順に取らない。
- 同意の `llmQuotes` が false なら、引用を空にする。
