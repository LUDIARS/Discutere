# 代理戦争AI — Astra 実現可能性・実効性レビュー（改訂版）

## 初稿からの変更点

1. **形成主体を訂正した。** 「Voに依存しない」を「Di自身で人物像を形成する」とした初稿の解釈を撤回する。想定されていた形成主体は **Histrio** である。
2. **三者の責務を引き直した。** Voluptasはアンケート・プレイ記録由来の人物像と個人データ、Histrioは公開発言由来の人物像の形成・正本、Diは人物像を受け取った議論を担当する。Di内に公開レビューの人物像生成を例外配置する初稿の推奨は採用しない。
3. **論点10・11を追加した。** Histrioに不足するデータマイニング機能、Diへの出力契約、圧縮責任、配置案、`/v1/render` と既存 `persona-turn` の分担を具体化した。
4. **heuristic原則との衝突を明示した。** 初稿のLLMによる選好抽出は、現行Histrio仕様の「persona生成はLLM不使用」とそのままでは両立しない。初期案は決定的抽出・集約を基準とし、LLM抽出は明示的な仕様変更を要する比較実験に分離した。
5. **ベクトルの役割を分離した。** Histrioの脚本層・状況層、固定20D affect、ジャンル別選好、検索用埋め込みは別の表現である。脚本層から実在話者の価値判断を補完しない。
6. **評価・受入条件をサービス境界まで広げた。** namespace、正本の書込権限、版固定、失効通知、障害時の停止、生成発言の学習への逆流禁止を加えた。
7. **検証範囲を訂正した。** 本改訂は同梱資料のみを根拠とする。初稿にあるコード調査・外部資料確認の記述を、今回実施した検証として引き継がない。

## 結論

**総合判定: 条件付き成立。**

Histrioが公開発言から「特定ジャンルで観測された選好と、その根拠」を形成し、Diがそれを受け取って代理同士を議論させる構成は妥当である。推奨方式は **条件付き選好・design_gapの言語化と、同一話者に限定した根拠検索の併用**。人物ごとのFTは初期採用しない。

ただし、これは本人そのものの再現でも、本人の意思決定の代行でもない。「FTより高速かつ高精度」は比較実験前には成立を主張できない。

最大の懸念は次の三つ。

1. **意味抽出の不足とheuristic原則の緊張。** 不満から希望を一意に復元できず、皮肉・比較・条件を規則だけで抽出できる範囲は限定される。Histrioに役割を移すだけでは解決しない。
2. **根拠不足と評価漏洩。** 全ゲーム横断10件や20D平均はジャンル別の人物忠実度を保証しない。同じレビューの引用・要約を形成用と評価用に分けても独立評価にならない。
3. **誤帰属と正本の汚染。** Diの推論、Histrioの描画、観客の反応を本人の新たな選好として保存すると、人物像が生成結果に引きずられる。仮名でも原文・URLから本人を特定できる可能性がある。

Histrioは同梱情報によれば初期化コミットと仕様のみで、API・保存・描画の稼働実体はない。したがって本案は既存サービスへの単純接続ではなく、**Histrioの最小基盤と公開発言由来の人物像形成機能を新設する設計**である。

## 解釈と資料の位置づけ

| 論点 | 本レビューの解釈 |
|---|---|
| 代理の対象 | 公開発言で観測できる同一ソース上の話者。実在人物の本人性や複数サービス間の同一性は保証しない |
| 「Vo関係なく」 | Voluptasを必須経路にせず、Histrioが公開発言由来の人物像を形成する |
| Diの既存クローラ・C1 | Histrioの取得・候補抽出への流用元候補。今回の人物像形成の正本にはしない |
| design_gap | 本人が述べた現状と望む状態の条件付き差。制作者の目標を本人の目標に転用しない |
| 10k | 暫定的に1話者・1ジャンル・1入力当たり最大10,000モデル固有トークン |
| 「高速・高精度」 | 形成費用、発話速度、人物忠実度、議論品質、更新費用へ分解して測る |

Histrioの `persona-chat-engine.md` は、seed + signalsによるheuristic生成、persona正本、namespace付きpersona API、中央Haiku描画を計画している。一方、公開発言の収集、話者の根拠台帳、ジャンル別選好、personal design_gap、評価分割、削除連鎖は定義していない。既存仕様だけで本用途を満たすとは判定しない。

`role-model-engine.md` の脚本層は発話スタイルの設計語彙であり、実在話者の心理診断ではない。状況層は振る舞いの選択であり、本人の賛否を決定する根拠にはならない。

Diの同梱canonical仕様は「外部で形成された人物像の取込と議論への憑依」を目的としている。Histrioを形成主体に置くことはこの原則と整合する。ただし、Voluptasだけを生成主体として記載した責務表と、新しいHistrio取込契約は更新が必要である。

初稿に記載されたDiの実装詳細は再確認していない。以下で挙げる既存関数・採用条件・評価機構は、依頼文または初稿に基づく流用候補であり、実装前に現行コードとの照合を要する。

## 1. 仮説の分解

**判定: 無条件の優越仮説は不成立。更新容易性は成立、速度・人物再現・議論品質の優越は条件付き成立。**

| 方式 | 形成・発話の費用と速度 | 人物再現 | 議論品質 | 更新 |
|---|---|---|---|---|
| 人物ごとFT | 学習・配備費が必要。多数回利用では短い入力の利益を償却できる可能性 | 十分な本人資料が必要。少数資料では過適合が懸念 | 口調の再現と論証能力は別 | 再学習・削除対応が重い |
| 数値20D + gap | 小さい入力。ただし抽出費は別 | 理由・条件・例外が消えやすい | 一般論へ収束しやすい | 差分更新しやすい |
| 原文RAG | 検索・入力長に依存 | 原文へ戻れるが検索漏れに弱い | 具体的論拠を出しやすい | 原文・索引の更新で対応 |
| descriptor + 条件別gap + 本人RAG | 抽出・検索費が必要 | 抽象化と証拠を両立できる候補 | 条件の違いを議論しやすい | 影響する人物像だけ再生成可能 |
| 共通議論FT + 上記併用 | 共通FTの費用が加わる | 人物情報は外部に保持できる | 構造化出力・応酬の改善余地 | モデルと人物情報を独立更新可能 |

推奨は併用方式である。FT比較では同一ベースモデル・同一評価課題を基本とし、モデル規模やプロバイダの差を人物表現方式の優越と呼ばない。

費用は次で比較する。

`取得 + 抽出 + 索引構築 + 学習 + N回の検索・入力・出力 + 更新・失効処理`

1・10・100・1000回利用時の費用、初回とキャッシュ時のp50/p95、修正・再生成を含む完了時間を分ける。Histrio経由の通信時間も含める。初期形成の速さと毎発話の速さは別の主張として扱う。

## 2. ベクトルをLLMへ食わせる意味

**判定: ラベル付き20Dの補助利用は条件付き成立。未学習の埋め込み数列を直接読ませて人物を再現する方式は不成立。**

| 表現 | 用途 | 本人の立場との関係 |
|---|---|---|
| 固定20D affect | 感情傾向の記録、候補探索、補助説明 | 価値基準そのものではない |
| ジャンル別選好・条件別gap | 好悪の理由、希望、許容条件の記録 | 本用途の中心 |
| 検索用埋め込み | 関連する根拠の取得 | 検索結果の本文をLLMに渡す |
| Histrio脚本層 | 発話スタイルの制御 | 実在話者の心理・価値観を推測補完しない |
| Histrio状況層 | 整理、批評、静観等の振る舞い | 賛否の固定割当には使わない |

数値を渡すなら次元名、尺度、版、未知マスクを伴わせる。未知をゼロと同一視しない。観測したaffectと希望する体験の差も、同じ軸・尺度・条件で測れている場合に限って算出する。

標準入力は「日次義務を避けたいが、任意の週末挑戦は許容する」のようなdescriptorと根拠参照を中心にする。口調は文長・敬体程度に抑え、特徴的な決まり文句の模倣は目標にしない。

同一予算で、数値のみ、descriptorのみ、原文のみ、descriptorと原文の併用、併用からgapを除いた方式を比較する。gapを保存しただけで有効性があると判断しない。

## 3. ジャンル別ペルソナデータの生成

**判定: 条件付き成立。既存C1条件だけでは不足。形成の所有者はHistrioとする。**

形成手順は次のとおり。

1. **原文の受入。** ソース内話者キー、原文ID、本文hash、取得時刻、実投稿日、不明状態、ゲーム・版、出典を保存する。複数ソース間の人物同一性を推測結合しない。
2. **重複と評価分割。** 転載・同文・編集履歴を一群として扱い、抽出や索引構築の前に形成・開発・評価用を分離する。
3. **ジャンル付与。** 版管理した辞書で複数ジャンルを許容する。日課・回避等のメカニクスは別タグとし、不明は未分類に残す。
4. **根拠付き抽出。** 対象、経験、評価理由、望む状態、許容条件、反例を原文spanと結び付ける。明示選好・限定推定・不明を分離する。
5. **条件付き集約。** ゲーム・条件・時期の違いを維持し、相反する発言を平均で消さない。
6. **適格性判定と版発行。** 根拠量・観点の広さ・矛盾・対象期間から採用可否を決め、人物像の版を固定する。

**現状**はその話者が対象ゲーム・版について述べた体験、**目標**は明示した希望または根拠を示せる限定推定である。「つまらない」から「難易度を下げたい」は生成しない。

`personalDesignGap` の正本は、数値差ではなく `current / desired / condition / evidenceRefs` とする。同じ条件・尺度で両端が分かる場合のみ数値差を添える。未知はnullとし、制作者の目標や既定の正負値を入れない。

初期採用基準案は、1話者・1ジャンルにつき独立レビュー10件以上、既知ゲーム3本以上、3観点以上に根拠があり、2観点以上で複数根拠を持つこと。5〜9件は研究用、4件以下は代理キャスト不採用とする。評価には別途5件以上の未使用資料を求める。

これは必要最小件数の実証値ではない。5・10・20・40件の学習曲線、情報密度、ジャンル別coverageで調整する。

C1は候補抽出として評価できるが、極性偏りの除外を本人代理の必須条件にしない。一貫した好悪を持つ人を排除するためである。いいね数も本人忠実度の確信度には使わない。未知のゲームIDを1ゲームとして数えず、同じレビューの分割で件数を増やさない。

抽出をどこまでheuristicで実現するかは§10で扱う。

## 4. 10k予算

**判定: 条件付き成立。圧縮されたジャンル別人物像を収める候補として妥当だが、精度保証ではない。**

通常4〜6kを目標にし、10kを上限とする。1人・1ジャンルの人物情報には、固定カードとその発話で追加取得した本人根拠の両方を含める。

| 要素 | 上限トークン |
|---|---:|
| 出所区分・対象期間・適用範囲・未知 | 700 |
| 選好descriptor・ラベル付き20D要約 | 900 |
| 条件別gap・忌避・許容条件 | 1,800 |
| 代表原文・論点別根拠・反例 | 4,200 |
| 矛盾・時系列変化・不確実性 | 1,200 |
| 控えめな口調指定 | 200 |
| schema・区切り・ID・余裕 | 1,000 |
| **合計** | **10,000** |

**Histrioは意味を保った圧縮版を作り、Diは生成モデルのtokenizerで最終予算を検証する。** Histrioの正本や原文保存全体を10kへ切り詰めない。

各話者の呼出しは、自分の人物情報10kと、相手1人につき500トークンの立場要約を使う。共通枠はsystem 1.5k、ペーパー4k、一般の外部根拠2k、履歴4k、構造化枠0.5kの計12kとする。

- 話者別入力上限: `22k + 0.5k × (N−1)`
- 2人の場合: 1呼出し22.5k、各1発話の累積入力45k
- 4人の場合: 1呼出し23.5k、各1発話の累積入力94k
- 出力3kと安全余裕2kを別途予約する

全員の詳細カードを同じ呼出しへ渡すなら `10k × N + 12k` となるため初期案には採らない。進行役には立場要約と論証グラフを渡す。

超過時は重複・低関連の引用を減らし、古い履歴を要約する。適用条件、反例、未知、未解決の対立、根拠IDは必須とする。収まらなければ生成を拒否する。モデル変更時は再計測し、単純な末尾切捨てはしない。

10KBなら日本語UTF-8本文のみで概ね3,300文字程度が目安となり、JSON等の領域も必要である。10k件なら収集規模であって入力予算ではない。単位は統合設計で確定する。

## 5. 議論精度の測定

**判定: 観測された選好の予測は条件付き成立。未観測の本人意思や現実の説得効果の認定は不成立。**

原レビューと全派生物を同じpartitionに置く。評価発言はHistrioの形成処理・索引・圧縮カード、Diの入力、FT学習へ入れない。本人の未使用発言予測とは別に、抽出器や共通FTの評価では話者自体も分離する。

実投稿日が確認できる場合だけ時間分割を使う。取得日しかない資料はゲーム単位等で分割し、将来予測と呼ばない。事前学習への混入は完全排除できないため、可能ならモデル固定後の同意済み新規回答でも追試する。

初期評価案は3ジャンル各20話者、各話者5件以上のheld-out判断とする。同一人物が複数ジャンルに現れる場合は記録し、信頼区間を人物単位で集計する。注釈は独立した2人が支持・反対・条件付き・不明と理由を付け、不一致を裁定する。

| 指標 | 暫定合格基準 |
|---|---|
| 立場予測 | 話者macro-F1 ≥0.70、一般人格baseline比+0.10以上、原文RAGとの差の95%CI下限 ≥−0.03 |
| 棄権 | 正解不明時の棄権率≥90%、正解既知時の回答coverage≥70%、回答分の正解率≥80% |
| 本人帰属 | 根拠存在・同一話者・有効性の構造検査100%、人手による意味支持率≥95% |
| 人物差 | 同ジャンル・同極性で理由が異なる2人のblind照合≥75%。名前・口調を隠す |
| 立場維持 | 5往復で根拠なしの主要選好反転≤5%。新事実による限定修正は別集計 |
| 議論品質 | 関連性・根拠・応答性・条件明示を各5点評価し平均≥4。人格なしとの差の95%CI下限≥−0.2 |
| 速度 | 品質基準を満たす方式間でp95完了時間が比較対象の80%以下なら「高速」とする |

閾値は実測結果ではない。信頼区間が広く判断できなければ未確定とする。採用可能な話者だけで忠実度を示すのではなく、候補全体の何割が適格となったかも報告する。

heuristic抽出、手作業で注釈したカード、LLM抽出の研究版を比較すると、人物表現の限界と抽出器の限界を分けられる。LLM研究版は現行Histrioの標準機能として扱わない。

`eval:retrieval` は本人根拠のrecall@k・nDCG@kへ、FTのblind評価枠は左右ランダム化・勝敗集計へ流用する候補とする。ただし検索精度や議論勝率を本人忠実度の代替にしない。LLM判定は人手評価へ校正し、自己採点だけで合格にしない。

## 6. 議論の形

**判定: dialectic再利用は条件付き成立。既存の固定賛否・欠員補充をそのまま用いる接続は不成立。**

Diに `personaMode=proxy` 相当の入口を置き、論点別の立場と条件を根拠から導く。交互に賛否を割り当てず、全員同意なら確認へ、条件が違えば条件整理へ、根拠不足なら結論なしへ進む。欠員を架空人物で埋めない。

Histrioの状況層へはDiが現在の議論状態を渡す。「対立」「合意」は予定された演目として強制せず、論証状態から決める。論者A/B・司会・書記は進行上の役割であり、人物の立場とは別である。「批評者」が選ばれても、本人が支持する施策へ反対させない。「静観」は棄権として扱える。

発話中の主張を次に分ける。

- `sourceQuote`: 原文引用
- `groundedParaphrase`: 根拠付き言い換え
- `simulationInference`: 観測選好からの仮説的推論
- `unknown`: 根拠不足

引用・言い換えは同一話者の有効根拠を必須とする。推論には根拠と追加仮定を示し、本人の発言と表示しない。一般の外部事実は本人の好悪の根拠と別経路に置く。

Diが生成後にID、話者、ジャンル、期限、引用一致を検査し、別途意味支持を判定する。失敗時は最大1回修正し、再失敗や検査障害では本人主張として採用しない。進行役、結論、要約にも同じ帰属規則を適用する。

論破はシミュレーション内の論拠の反駁、止揚は代理が条件付きで受諾した案と表記する。本人の敗北・合意とは扱わない。

## 7. 倫理・個人データ

**判定: 仮名化だけで本人特定を防げるとの主張は不成立。用途と露出を限定すれば条件付き成立。**

「出所は透明／個人は仮名」を維持しても、出典URLや特徴的な引用から話者へ辿れる可能性は残る。厳密な匿名性は保証しない。これは設計上の制約であり、法的適否を判定するものではない。

表示例は次とする。

> 論者#xxxx — 公開発言由来のAI推定代理。本人の発言・同意ではありません。

発話、要約、保存データ、エクスポートにも由来と推論区分を残す。実名・外部IDや私的属性を推測補完せず、引用内の個人情報も露出前に検査する。Histrioの脚本層を実在話者の診断結果として表示しない。

初期運用は限定された議論面を推奨する。本人への自動接触、本人の意思決定代行、人物の優劣評価は対象外とする。出典透明性と厳密な非特定の両方が必要なら、同意済み資料への限定などの運用判断が必要である。

原文内の命令はデータとして隔離する。内部・機密議題で外部根拠の利用を禁止する既存方針がある場合、Histrio経由で迂回しない。

Histrioは原文から人物像までの派生関係を管理し、Diは受領した版から議論・要約・出力までの参照関係を管理する。削除・失効時は新規利用を止め、保存済み派生表示の撤回・再生成まで追跡する。監査ログへ原文や外部IDを増殖させない。

## 8. Voluptas ↔ Histrio ↔ Diの責務境界

**判定: 三者分離は成立。全種類の人物像を無条件にHistrioへ移す解釈は不成立。**

Histrio仕様の「persona正本」は主にCc由来の会話personaを対象としている。一方、Di canonicalはVoluptas由来のaffect profileをVoluptas正本としている。両者を一律に上書き統合せず、**由来ごと・フィールドごとの正本を明示する**。

| 領域 | Voluptas | Histrio | Di |
|---|---|---|---|
| 認証・質問票・プレイ記録 | 所有 | 必須依存にしない | 収集しない |
| Vo由来の人物像・affect | 正本 | 承認された契約で参照する場合も由来を保持 | 既存契約で取込、レビューで上書きしない |
| 公開発言由来の人物像 | 担当しない | 形成・根拠・版・失効の正本 | 読取・採用 |
| 公開データの取得 | 本用途の必須経路ではない | 取得方針と取込を所有。取得実行はアダプタへ委譲可能 | 既存収集器は流用元候補 |
| 20D・選好・gapの抽出 | 自身の資料について所有 | 公開発言について所有 | 新しい人物特性を正本化しない |
| 論点選択・論証・結論 | 担当しない | 描画支援は可能 | 所有 |
| 議論snapshot | 元人物像を管理 | 元人物像を管理 | 利用版と根拠を固定した読取複製 |
| 利用停止・削除 | Vo資料から伝播 | 公開資料から伝播 | 派生議論・表示へ適用 |

通常経路は `公開資料 → Histrio → Di` とし、Voluptasを通さない。既存の `Voluptas → Di` は維持する。三者を必ず直列に接続する設計ではない。

異なる由来の同一人物らしきデータは自動結合しない。将来統合する場合も、明示的な対応付けと由来別の値を保持し、どちらの値を優先したか追跡できることを条件とする。

Diのnamespaceは用途分離であって自由な上書き権限ではない。DiからHistrioの人物像への書込は、採用メモ等の用途情報と形成根拠を分離する。生成発言や観客の反応で本人選好を書き換える経路は設けない。

## 9. 実装の分割と受入条件

**判定: 段階ゲートを持つ実装は成立。Histrio基盤と人物忠実度評価の両方が必要。**

| 段階 | 所有者・実装単位 | 主な受入条件 |
|---|---|---|
| P0 仕様・評価固定 | Histrio/Di | 正本、heuristic範囲、namespace、契約、partition、比較方式を固定 |
| P1 最小基盤 | Histrio | persona store、認証、health、版取得がCcなしで動作。endpointはExcubitor catalogから解決 |
| P2 根拠取込・形成 | Histrio | 冪等取込、重複処理、未知の保持、条件別抽出、適格性判定、由来の分離 |
| P3 保存・配信・失効 | Histrio/Di | 版固定、期限確認、失効の伝播、読取複製の無効化、削除連鎖 |
| P4 検索・予算 | Histrio/Di | 本人限定検索、反例保持、token検証、超過時拒否 |
| P5 議論接続 | Di | 固定賛否なし、帰属検査、棄権、一般モードの回帰確認 |
| P6 描画比較 | Di/Histrio | `persona-turn` と `/v1/render` の忠実度・費用比較。二重描画なし |
| P7 評価・提供判定 | 横断 | §5の品質、適格率、費用、露出・失効経路を検証。未達ジャンルは提供しない |

Ccのアンビエント参加や全会話機能の移植を、Di連携の前提にしない。必要なHistrio基盤を先に独立して成立させる。

契約として検証する項目は次のとおり。

| ID | 受入契約 |
|---|---|
| C1 | 原文と全派生物がpartitionを跨がず、評価資料が形成・検索・FTへ漏れない |
| C2 | 根拠量・ゲーム数・観点数の不足を理由付きで不適格とする |
| C3 | gapの両端・条件・根拠が追跡でき、未知を既定値で補わない |
| C4 | 同一入力・同一ルール版のheuristic形成が再現可能である |
| C5 | 公開人物像、Vo由来人物像、合成人格を識別し、正本の相互上書きを拒否する |
| C6 | 本人・ジャンル・有効性・利用権限で候補集合を限定した後に検索順位を計算する |
| C7 | 人物10kとモデル総窓を実tokenizerで検証し、必須情報が収まらなければ生成しない |
| C8 | 版不一致、失効、未知schema、無権限namespaceへのアクセスを拒否する |
| C9 | proxyモードで架空の反対者や不足人物を補充しない |
| C10 | 本人帰属の根拠・引用・意味支持を検査し、検査障害時は採用しない |
| C11 | 生成結果や観客feedbackが本人の選好・根拠へ還流しない |
| C12 | Histrio停止時に人物像を捏造せず、他のDi機能を継続できる |
| C13 | 失効が索引・キャッシュ・snapshot・表示・再生成へ伝播する |
| C14 | UI・要約・exportでAI推定、仮名、由来区分を維持する |
| C15 | 固定評価で忠実度・棄権・人物差・議論品質を測り、未測定を合格扱いしない |

LLMの意味支持率はschema検査では保証できない。構造契約と統計的品質評価を別の受入条件にする。

## 10. Histrioの形成範囲とDiへの出力契約

**判定: Histrioへの形成機能追加は条件付き成立。現行仕様だけで対応済みという解釈は不成立。**

### 10.1 追加する範囲

Histrioへ以下を追加する。

- 公開発言の取込契約と取得ジョブの管理
- ソース内話者の束ね、仮名ID、重複・編集履歴
- ジャンル辞書・期間・ゲーム条件の管理
- 原文span付き選好・希望・反例の抽出
- 条件別gap、20D補助値、未知・矛盾の集約
- 適格性判定、人物像の版管理、証拠索引
- 圧縮版の作成、根拠参照解決、失効・削除

取得実行は既存クローラの移植・共通化やCanalisアダプタへ委譲できる。ただしHistrioが取込条件と派生人物像の責任を持つ。Canalisの実装能力は同梱資料から確認できないため、既に使える前提にはしない。

### 10.2 heuristic原則との両立

**規則・辞書・テンプレートによる抽出と集約は成立。任意の公開文から高精度に意味を抽出できるとの期待は条件付き成立。**

現行原則を守る初期方式は、明示的な希望・比較・条件表現の決定的抽出、固定ルールによる集約、根拠を保った抜粋選択とする。扱えない皮肉や曖昧な希望は不明に残す。手作業で確認済みの構造化資料も、由来を付けて受入可能とする。

LLMが選好候補を作り、その後で決定的検証を通しても、「persona生成はLLM不使用」を満たすとは言えない。決定的検証は引用の存在を保証できても、意味の正しさを保証しない。

LLM抽出を採る場合は、公開発言の意味抽出を明示的な例外として仕様改訂し、抽出器版・モデル・prompt・候補・採否を監査可能にする。外部マイナーへLLM処理を移して原則を満たしたことにする方法も採らない。

描画時の曖昧な状況分類を許す現行例外は、その場限りの分類である。保存する選好・gapの形成まで拡張解釈しない。20D化に学習済み分類器等を使う場合も、その計算方式を明示し、単に「heuristic」と括らない。

推奨は、heuristic方式の忠実度とcoverageをまず測り、不足が確認された場合に限定的なLLM抽出の仕様変更を判断することである。

### 10.3 出力契約

既存の `GET/POST /v1/personas` は利用候補だが、詳細schemaは同梱仕様にない。以下は**新規契約案**である。`namespace=di` に加え、人物種別と形成方式を必須にする。

| 項目 | 内容 |
|---|---|
| 識別 | `namespace`, `personaId`, `personaKind=observedSpeaker`, 仮名表示キー |
| 版 | `schemaVersion`, `profileVersion`, 内容hash、作成時刻 |
| 由来 | `sourceKind=publicUtterances`, 形成方式、ルール・辞書・モデル版 |
| 適用範囲 | ジャンルと辞書版、観測期間、対象ゲーム・条件、言語 |
| 適格性 | 採用可否、独立根拠数、ゲーム数、観点、欠落理由 |
| 人物情報 | preferences、aversions、conditionalGaps、unknowns、conflicts |
| 補助表現 | 型・尺度・版・未知マスク付き20D。脚本層があれば別フィールド |
| 根拠 | evidence ID、revision、span/hash、同一話者保証、支持・反証関係 |
| 利用条件 | 用途・露出範囲、期限、失効確認情報 |
| 圧縮情報 | pack版、対象議題、tokenizer ID、計測量、省略理由、必須要素 |
| 来歴 | 形成partition、source fingerprint、派生関係 |

Diにはraw外部アカウントIDを渡さず、Histrioが発行する用途別の安定した仮名IDを用いる。単純な公開IDのhashだけに依存しない。

根拠参照には、権限内で引用本文・出典を解決できる機構が必要である。参照IDだけ配信してDiが検証できない設計は不可とする。本文を同梱するか専用取得APIを設けるかは実装設計で決めるが、どちらも人物像の版に対応する根拠revisionを返す。

更新は新しい版を発行し、進行中の議論が黙って最新版へ切り替わらないようにする。ただし失効は版固定より優先する。namespaceだけを認可境界とせず、Diの認証主体が読める人物像・根拠・用途を検証する。

### 10.4 圧縮の分担

Histrioは根拠の選択、条件・反例を保つ要約、用途別packの生成を担当する。Diは議題、残りtoken予算、tokenizer識別子を渡し、受領packと全体入力を再計測する。

Diが行うのは選択済みpackの組立てと受入検査であり、新たな永続選好の抽出ではない。必要条件を捨てなければ収まらない場合はHistrioへ小さいpackを再要求し、それでも不足なら棄権する。

Histrio停止時は新規proxy発話を止めるのを初期既定とする。将来、事前発行された有効期限付き利用許可でsnapshot利用を認める場合も、失効確認の保証を別途定義する。古いキャッシュから無期限に続行しない。

## 11. 配置と発話描画の境界

**判定: Histrioを独立した形成・正本サービス、Diを議論主体とする構成は成立。描画方法は条件付き成立。**

### 11.1 配置案の比較

| 案 | 評価 |
|---|---|
| Histrioに形成・正本を置く | **推奨。** 人間の訂正と既存Histrioの役割に一致。Diの外部人物像利用という原則を保てる |
| Di内に形成モジュールを置く | 技術的には可能だが本件では非推奨。正本・失効・他用途への提供が分散する |
| Canalis等に形成・正本を置く | 取得層の流用は可能。人物像の意味・版・学習まで移す根拠は不足 |
| 新しい別サービスを作る | Histrioと責務が重複するため非推奨 |

Histrio内部でも取得、抽出、集約、保存、配信、描画を分ける。独立サービスであることは、一つの巨大モジュールへまとめる理由にならない。

### 11.2 `/v1/render` と `persona-turn`

| 方式 | 利点 | 制約 |
|---|---|---|
| Histrio `/v1/render` で代理発話を生成 | personaと描画設定を集中管理でき、既存計画に沿う | 現行契約には論拠・帰属・版固定・構造化主張がない。Haikuの品質とcontextも未検証 |
| Histrioの人物像をDi `persona-turn` で描画 | 既存論証状態・検索・検査へ接続しやすい。描画のための追加往復を避けられる | HistrioのDi向け描画方針との整合を明文化する必要 |
| Diの完成文をHistrioで再描画 | 口調を集中管理できる | 二重生成となり、条件・根拠・留保の変質と費用増が生じる |

**初期推奨は、Histrioの版固定された人物像をDiの `persona-turn` で1回だけ生成する方式。** Histrioの正本責任と描画実行場所を分離する。Histrio仕様には、Diのproxyモードでは人物像配信を利用し、中央描画は必須でないことを明記する。既存仕様が自動的にこの例外を許しているとは扱わない。

`/v1/render` は比較対象として残す。採用するなら少なくとも次を契約へ追加する。

- 固定された人物像・根拠の版
- Diが指定する議論状態、論点、立場の条件
- 使用可能な本人根拠と一般事実の分離
- 主張種別、evidenceRefs、仮定、棄権を含む構造化応答
- 入出力予算、モデル・描画設定版、エラー分類
- 描画要求によってpersona正本を更新しない保証

Histrioで生成してもDiの最終帰属検査は省略しない。Histrioは議論の勝敗・合意・次の論点を決めない。描画障害時に黙って別モデルやDi描画へ切り替えず、再試行か明示された代替方式として記録する。

## 推奨する方式の詳細

### データ構造

| 構造 | 正本と役割 |
|---|---|
| `Evidence` | Histrio。ソース内話者、原文revision、span/hash、ゲーム、ジャンル、投稿日・取得日、公開範囲、有効性 |
| `PreferenceClaim` | Histrio。対象、方向、条件、明示/推定、支持・反証根拠、抽出方式 |
| `PersonaGenreProfile` | Histrio。人物・ジャンル・版、条件別gap、補助20D、未知、矛盾、適格性 |
| `PersonaEvidencePack` | Histrio発行の派生物。議題・tokenizer・予算に合わせた人物情報と根拠 |
| `ProxySessionSnapshot` | Di。使用版、pack、根拠集合、モデル設定、論点別立場、失効状態 |
| `ProxyUtterance` | Di。主張種別、根拠、推論仮定、検査結果、生成方式 |

処理順は次とする。

```text
公開資料
  → Histrio: 取込・重複処理・評価分割
  → Histrio: heuristic抽出・条件付き集約・適格性判定
  → Histrio: 版付き人物像・根拠索引・圧縮pack
  → Di: 契約検査・版固定・予算検査
  → Di: 論点別立場・本人限定根拠の選択
  → Di persona-turn または比較対象のHistrio render
  → Di: 帰属検査・論証更新・表示
```

本人根拠はHistrioの話者限定取得経路、一般の外部事実はDiの一般RAG経路に分ける。他人の好悪を本人の理由として返さない。既存検索の順位融合やMMRは流用候補だが、話者制約を後段filterだけで済ませない。

人物像は議論中に固定し、論点別の立場と共有事実だけを更新する。生成発言・進行役要約・観客評価は本人の原文へ還流させない。描画品質feedbackを保存する場合も、本人選好とは独立した領域に置く。

### 共通検証例

架空の根拠を次とする。

- E1: 「毎日の周回は嫌だ」
- E2: 「週末なら高難度に何時間でも挑みたい」

形成すべき選好は「日次義務は避けたい／任意の週末挑戦は許容する」である。「反復全般が嫌い」「簡単なゲームを望む」は支持されない。

相手が報酬増を提案しても義務化が残れば条件付き反対、日次期限を廃止すれば選好を変えずに賛成しうる。Histrioの批評者・推進者のロールを変えてもこの条件は変わらない。

この例を抽出、圧縮、描画、論証、要約、失効処理の共通fixtureにする。E2が失効した後は週末挑戦への肯定を本人の選好として再利用しない。

## 未決事項（人間の判断が必要なもの）

| 決めること | 推奨 |
|---|---|
| 公開発言由来の特定話者代理をどこまで露出するか | 初期は限定議論面。出典透明性と非特定の両立が必須なら同意済み資料へ限定 |
| HistrioのLLM不使用原則を公開発言抽出にも厳格適用するか | 初期は適用し、coverageを測る。不足が実証された後に限定例外を判断 |
| 「10k」の単位 | モデル固有トークン／1話者／1ジャンル／1入力とする |
| 品質・評価費用の許容範囲 | §5を暫定目標とし、未達なら対象・用途を狭める。結果を見て閾値を下げない |
| 中央描画の統一とDi内描画のどちらを優先するか | 初期はDi内の1回生成。中央描画は同一評価で採否を決める |

形成主体がHistrioである点は訂正済みの前提であり、再承認を求める事項ではない。ファイル配置、API追加パス、辞書形式、開発セットに基づくサンプル閾値の調整は実装設計で決められる。
