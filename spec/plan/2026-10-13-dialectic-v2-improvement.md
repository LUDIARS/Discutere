## 1. v2 の目標

**「やり取りの記録」と「結論」が一致し、決着しなかったもの・崩れたものを結論が前提に使わない議論**にする。

受入の物差し (同じ議題で #144 と比べる。§6):
1. 進行役の集計が実際のやり取りと一致し、打ち切りは打ち切りと言う。
2. 連鎖の最後の一手を誰が打つかで勝敗が決まらない。
3. 撤回・認めた論拠、決着しなかった論点の命題を、止揚・最終結論が前提にしない。
4. 引用した声の番号と本文が全論点で一致し、記録から検証できる。
5. Fable / Astra の同観点レビューで 4/5 以上。

## 2. 変更一覧 (優先度順)

### P1. 打ち切りを「一段落」と言わない・集計の内訳を告げる (Fable 重大 1)

- 現象: #144 の 3 論点とも `exchangeTurns` (16) に達して打ち切り。各論点で未応答の反論が 3 件残ったのに、進行役は「一段落しましたね」と告げ、未応答を「崩れずに残った」に含めた。
- 原因: `exchange-runner.ts` のまとめ文が `settled()` (自然終了) と `cutRemaining()` (上限) を区別しない。`standingCount` は verdict≠refuted を一律に「残った」と数える。
- 設計:
  - `runGroundExchange` が終了理由 `settled | turn_cap` と打ち切り件数を返す。
  - まとめ文を 2 種に分ける: 自然終了「論拠のやり取りが落ち着きました」/ 上限「応答ターンの上限 (N) に達したので、応答待ち M 件 (誰→誰) を未決のまままとめに入ります」。
  - 集計を内訳で告げる: 陣営ごとに `反論なし a / 守った b / 未決 (打ち切り) c / 崩れた d` (`GroundExchange.tally(side)` を新設)。
  - 冒頭サマリ・md の「残った論拠 x/y」も同じ内訳にする。

### P2. 深さ上限の「最後の一手」バイアスをなくす (Fable 重大 2)

- 現象: `argumentDepth=4` (偶数) で、深さ 0 の持ち主 A → 1 B → 2 A → 3 B → 4 A (打ち切り) となり、論拠の持ち主が常に最後の一手を打つ。打ち切りは `contested` → 根拠状態 `defended` に写すため、連鎖で崩れた論拠は 13 件中 0 件 (崩れたのは本人の「認める」3 件だけ)。
- 原因: `exchange.ts` の `groundStates()` が `contested` を `defended` に写す (v1 で「最後に答えた側を勝たせない」つもりが、逆に持ち主有利になった)。
- 設計:
  - 根拠状態に **`unsettled` (未決)** を足す (`store.ts` の `GroundState`)。`contested` は `defended` ではなく `unsettled` に写す。
  - `goal.ts` の論破判定: 崩れた (`challenged`/`conceded`) だけで判定し、`unsettled` は「残った」にも「崩れた」にも数えない。一方の根拠が「崩れた + 未決」だけ (守った・反論なしが 0) なら論破ではなく **結論なし (未決)**。
  - 合わせて `argumentDepth` 既定を 5 (奇数) にし、最後の一手を反論側に来させる (持ち主が答える/認める番で打ち切りになるのは上限ターン時だけ)。
  - 移行: 既存行の `defended` は読み出し互換のまま。

### P3. 撤回・崩れた論拠と未決の論点を、止揚・結論の前提に使わせない (Astra 重大 1・2、Fable 重大 3)

- 現象:
  - 論点 2 で高瀬が「G3 の復帰導線という推論は守れません」と認めた (撤回) のに、止揚と最終結論が「休眠者が仲間と戻る再接続」を中心に据えた。
  - 論点 3 の止揚が「ビジネスとして正解か」を「仲間内の話題になるか」に判定基準ごと置き換えた (解決ではなくすり替え)。
  - 最終結論は論点 1 (結論なし) を載せず、論点 1 で決着しなかった「メカニクスが土台」を前提にした。人物の取り違え (指摘した人と撤回した人を混同) もある。
- 原因: 止揚生成 (`synthesis.ts`) と結論生成 (`conclusion.ts` → `generateConclusion`) に、根拠の状態 (崩れた/撤回) と論点の決着を「使ってはいけない前提」として渡していない。批准も「自陣営の根拠が保存されたか」しか見ない。
- 設計:
  - 止揚の入力から `conceded`/`challenged` の根拠を外し、「崩れた論拠 (前提に使わない)」として別枠で明示する。`preserves[]` に崩れた根拠 ID を入れたら折衷ゲート (`elevation-gate`) で不合格。
  - 止揚の批准に「論点の問いに答えているか (判定基準を置き換えていないか)」を足す (`ratify` のチェックリスト)。置き換えなら reject → 修正ループ → 不成立なら結論なし。
  - 結論生成: 論点ごとの決着 (区分 + 理由 + 残った/崩れた/未決の根拠) を **決着表としてそのまま本文に写す** (LLM は要約部だけ書く)。指示に「結論なし・未決の論点の命題を他論点の結論の前提に置かない」「撤回・崩れた論拠を根拠に使わない」「人名を付けるのは決着表の事実だけ」を加える。
  - 結論文の検査 (判定 LLM、小): 決着表と矛盾する主張・撤回済み命題の再利用を検出したら 1 回だけ作り直す。

### P4. 声の番号を固定し、記録に一覧を載せる (Astra 重大 3、Fable 注意点)

- 現象: 論点が変わると同じ V 番号が別の声を指す (論点ごとに `voiceCache.lookup([issue.title, theme])` で引き直し、番号を 1 から振るため)。記録 md に声の本文が無く、引用の正誤を検証できない。撤回済みの誤推論が別番号で再登場した。
- 設計:
  - セッション単位で声に固定番号を振る (ペーパーの保存声 `discussion_paper_voice` の ordinal を正本にする。保存が無い経路は議論開始時に採番して保存)。論点ごとの声ブロックは固定番号で出す (`issue-voices.ts`)。
  - md 書き出し (`conclusion-markdown.ts` と運用スクリプト) の末尾に「声の一覧 (番号・本文・出所)」を載せる。個人アンカーは出さない (既存方針)。

### P5. 「言葉の範囲のずれ」を対立の型に加える (Fable 重大 4)

- 現象: 論点 1 は賛成が「メカニクス」に協力・人間関係まで含め、反対は含めなかった (定義のずれ)。v1 は「事実対立」と分類し、照会の結果「証拠 10 件は A を支持」と「結論なし」を同じ文に並べた。
- 設計:
  - `tension.ts` の型に `definition` (定義・範囲のずれ) を足す。判定で検出したら事実照会に進まず、結論なしの理由を「定義の不一致: 賛成は X を含め、反対は含めない」と明記する。
  - 事実照会の結論文 (`renderOutcomeLine("none", …)`) は「照会では A 側の根拠が支持された (根拠 V… の n 件)。ただし止揚・論破には至っていない」と、支持と区分を分けて書き、証拠の声番号を載せる。

### P6. 再反論の指名で元の反論者を優先する (Fable)

- 現象: 応答者を「相手陣営で発言数最少」で選ぶため、連鎖の途中で別の人が別の筋で答え、論旨が乗り換わる。
- 設計: `exchange-runner.ts` の `pickSideSpeaker` を「応答対象の論拠の持ち主 (深さ ≥1 なら元の反論者) が陣営にいればその人、いなければ発言数最少」に変える。

### P7. 止揚の批准結果を露出に出す (Fable)

- 設計: 止揚文の直後 (または md の決着表) に両陣営の accept/reject と保存された根拠 ID を載せる。批准の無い止揚は止揚と呼ばない (結論なし (折衷))。

### P8. ゲームの仕組みと矛盾する前提の検出 (Fable / Astra 観点 7)

- 現象: 友情コンボの発動条件 (自分のモンスターに当たる) から「人との交流が必須」と飛躍、設計意図を観測済みの心理効果として扱う。
- 設計: 前提ルール判定 (`rule-check.ts`) にペーパーのメカニクス表 (#2852 で議論でも載る) を渡し、仕組みの説明と矛盾する前提を含む反論を `mechanic_mismatch` として question に格下げし、進行役が仕組みの説明を一言添える。

### P9. 論拠のデータ必須と声の偏りの明示 (両レビュー観点 6)

- 設計: 定立の論拠で V 参照 (データ) が無いものを「データなしの演繹」として区別して集計・表示する。論点ごとに使われた声の内訳 (続けている人 / 離脱・不満 / 不明) を進行役のまとめに一言載せ、偏りがあれば「離脱者・新規の声が無い」と不足を明記する。

### P10. 版の識別 (neco「議論 ver 上げます」)

- `flow.dialectic.version` (既定 `"v2"`) を config に置き、`flow_conclusion` / ペーパー経過に版を記録する (読み出し・比較用)。v1 の挙動に戻すフラグは持たない (版は記録のみ)。
- 学習ビュー・md 書き出しに「議論エンジン v2」と表示する。

### P11. 運用上の不具合 (付記)

- `claude cli exit 1` で stderr が空のとき原因が残らない (#143 で Sonnet 系と既定モデルが 09:20 以降に連続失敗、後で再現せず)。`claude-cli.ts` で exit≠0 のとき stdout の先頭も error に含め、cost log に残す。
- 進行役の引用は「文の区切りまで」だと結論文が切れることがある (r3 t24)。対象論拠の結論文を含む範囲 (末尾側優先) で切り、省略時は「…」を明示する。

## 3. 実装の分け方 (次のセッション)

1 PR に集約する (AI 実装は 1 PR)。順序の目安:
1. P2 (根拠状態 `unsettled` と論破判定) → P1 (集計の内訳とまとめ文) — 集計の土台
2. P3 (止揚・結論の前提の制約と検査) — 結論の正しさ
3. P4 (声の固定番号と一覧) — 検証可能性
4. P5 / P6 / P7 / P8 / P9 / P10 / P11

テスト: 既存 `tests/flow/dialectic-*.test.ts` を拡張する。最低限、
- 上限打ち切りで「一段落」と言わず内訳を告げる / 自然終了は「落ち着いた」
- 深さ上限の打ち切りが `unsettled` になり、持ち主の勝ちにならない / 一方が「崩れた + 未決」だけなら結論なし
- 崩れた根拠を `preserves` に入れた止揚が折衷ゲートで落ちる
- 結論本文に全論点の決着表が載り、結論なしの論点が抜けない
- 声の番号が論点をまたいで同じ本文を指し、md に一覧が載る
- `definition` 型の対立が事実照会に進まない

## 4. 変えないこと

- 結論は 止揚 / 論破 / 結論なし の 3 区分 (#2799)。合意判定は戻さない。
- 人が指定した論点は打ち切らない (#2848)。
- 議論は Discutere 内のデータだけで行える (外部収集はしない経路を保つ。#2852)。
