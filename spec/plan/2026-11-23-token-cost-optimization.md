## 1. 方式

| # | 施策 | 変更 | 見込み |
|---|---|---|---|
| 1 | 判定モデルの振り分け | 折衷ゲート (elevates 1 文だけを見る) を最終判定モデルから通常の判定モデルへ (`SynthesisLoopArgs.gateModel`)。批准は最終判定モデルのまま | 1 論点で Fable 3 回 → 0 回 |
| 2 | 前置きを小さく・毎回同じに | `ClaudeCliClient` を隔離して起動 (`llm.claudeCliIsolate` 既定 true、cwd `llm.claudeCliHome` 既定 `%LOCALAPPDATA%/Discutere/llm-home`、`--tools=` `--strict-mcp-config` `--disable-slash-commands` `--exclude-dynamic-system-prompt-sections` `--setting-sources local`)。main が一度だけ既定を決めて全呼び出しに効かせる | 1 回あたり 1/10〜1/14 (実測) |
| 3 | 呼び出しを減らす | 定立に `answer` (論点への yes / no) を申告させ、立場と合えば向きの判定 LLM を呼ばない (食い違えば従来どおり判定)。「認める」の中身の確認は**省かない**: 材料の欄が空でも本文が反論の応答があり (golden `dlx-stance`)、省くと誤って論拠を崩す。2 の隔離で判定 1 回は約 $0.01 になるので節約より正しさを取る | 1 論点で最大 2 回減 |
| 4 | まとめを参照して話す | 応酬の発言者には両陣営を要約で渡す (`render_position_compact`: 応答する連鎖の根の根拠だけ詳しく、ほかは 1 行) | 発言の指示文が短くなる。焦点 |
| 5 | キャッシュを残す (セッション維持) | 指示文を「変わらない部分を先に」並べ替え (ペーパー → 前提ルール → 論点と声 → 両陣営の要約 → 発言者 → 応酬 → 指示)。同じ議論・同じモデルの連続した呼び出しで先頭がキャッシュに当たり続ける | 2 回目以降の呼び出しが安くなる |

### 1.1 「セッションを維持して話す」の扱い

claude のプロンプトキャッシュは CLI のプロセスや会話ではなく **前置きの先頭一致** で当たる (5 分程度の期限)。
2 の隔離で CLI 自身の前置きを毎回同じにし、5 の並べ替えで議論の共通部分 (ペーパー・前提ルール・声) を先頭にそろえれば、
同じ議論の中では単発の呼び出しのままでもキャッシュが残る。会話の履歴を引き継ぐ方式 (`claude -p --resume`) は履歴が
積み上がって 1 回あたりの読み込みが増えるので既定にしない。実測で単発 + 先頭一致と比べ、安い方を採る (§3)。

## 2. 変えないこと

- 判定の種類と順序 (形の検査 → 判定 LLM)、結論の決着表、深掘り。
- 批准は最終判定モデル (止揚の採否は結論を左右する)。
