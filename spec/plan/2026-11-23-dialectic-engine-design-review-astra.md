# Discutere 議論エンジンの設計評価 — Astra

**総合評価　3 / 5。** 論点ごとに異論と譲歩を追える骨格はよい。一方、ある説明が応酬を生き残ったことから、ゲームの変更を勧めてよい条件までの間に飛躍がある。

目的は、同じ仕様を違う遊び手の立場から読み、資料とプレイヤーの経験で説明を吟味して、作り手が「何を試すか」「何が分かるまで判断を保留するか」を選べるようにすることだ。以下は e796c5a を基準にした仕様の評価であり、10 月の v2 案と 11 月の人物像・ゲームの型の案は提案として評価した。

## 1. 目的との適合　重大

主張・データ・論拠・限定を分けた効用は、同じ声を保ったまま、その解釈だけを撤回できる点にある。「友人と復帰した」という声は経験の記録として残る。一方、その一例から「協力機能を追加すれば休眠者が戻る」と導くには、対象者と復帰の条件を示す必要がある。論拠を一件ずつ攻める進行は、この飛躍を読者に見せられる。

止揚・論破・結論なしは、議場で何が決着したかを表すには十分である。ただし、一方の根拠がすべて崩れても、他方の施策の効果は未検証のまま残りうる。また、事実照会で疑問が解けた場合も大分類は「結論なし」になる。各論点の決着に「作り手が今選べる行動」「適用する遊び手・条件」「判断が変わる観測」を添えたい。例えば復帰施策なら、休眠期間を揃えて招待の有無と復帰後の継続を比較する、という次の一手まで書ける。資料が足りなければ採否を保留するだけでも有用な結論になる。

根拠　`spec/feature/flow/dialectic.md` §1、§2.6、§4.5、§6。`spec/plan/2026-10-13-dialectic-v2-improvement.md` P3、§6。

## 2. 役割と進行　注意

進行役が問いを分解し、賛否が論拠を出し、意見役が声から別の視点を持ち込む分業には意味がある。輪番から対象を指定した応答に移ると、誰のどの推論に答えたかが残る。開始時の賛否固定は毎ターンの立場反転を防ぐが、「初回の導線は短くしたい」「上級者には探索の余地を残したい」は同じ人物が両方支持できる。全論点で配役を守らせると、こうした条件付きの一致まで対立として処理するおそれがある（推測）。

価値軸をセッション中固定し、賛否・条件付き・材料不足は論点ごとに選ぶ方式を推す。代理議論には、二人の立場が分かれないときはその理由を残す先例がある。分解時には、人が承認する各問いに対象集団と判断基準を一行ずつ添える。収束の三信号のうち、票の集中と新規主張の枯渇は、重要な反論が未応答でも同時に立つ。人の指定論点を最後まで扱う規則を維持し、自動論点も未応答のまま止めた場合は理由と件数を残す。

根拠　`spec/feature/flow/OVERVIEW.md` §4–5、`discussion.md`「ステップ詳細」、`dialectic.md` §2.6、§6、`proxy-debate.md` §2。7 月再設計の `01-persona-state.md`、`02-turn-scheduling.md`、`09-paper-gate-debatability.md`。

## 3. 評価・判定と呼び出し費用　重大

| 仕組み | 得られる判断と、残る限界 | 設計上の扱い |
|---|---|---|
| レンズ別投票 | 観点別にどの発言が支持されたかを示す。候補順を変えても、票から実プレイヤーの支持率は分からない。 | ラウンドの見どころに使う。決着と次の行動が同じなら追加投票を省く。 |
| 前提ルール・立場の向き | 相手の限定を外した攻撃や賛否の反転を検出する。一部への正当な譲歩も逆向きに見えうる。 | 対象 ID と引用は先にコードで検査し、意味の判定には対象箇所と理由を残す。 |
| 「認める」の検査 | 追撃を譲歩と誤記するのを防ぐ。誤って受理すると根拠の状態が変わる。 | 状態変更前に残す価値が高い。何を認めたか一つの論拠に限定する。 |
| 型分類・事実照会 | 定義、価値、事実で次にすべき仕事が変わる。検索結果の件数だけでは因果や効果量を判定できない。 | 問いを分け、照会には資料の種類と適用範囲を返す。必要な測定がなければ保留する。 |
| 折衷ゲート・両側批准 | 単なる併記を検出し、両側が保存されたと認める根拠 ID を記録できる。過半数を守っても必須条件を一つ失えば案は使えない。 | 両側が先に必須条件を一件指定し、批准時にその条件と元の問いへの回答を示す。該当候補がある場合に費用をかける。 |

改善フローの design_gap は投票と別の量である。射影計算は再現できても、入力する体験変化はモデル予測であり、障害時の辞書方式は文面の感情を拾う。予測と代替方式を同順位表で競わせると、採用理由が説明できない。方式を表示し、予測できた意見だけで順位を算出する方がよい。費用評価では旧反定立の呼び出し数を現行の見積もりに転用せず、論点別に応酬・検査・批准の回数、待ち時間、結論が変わった件数を記録する。usage 未取得の経路は別集計にする。

根拠　`spec/feature/flow/discussion.md` step 6、`improvement.md`「機械計算による評価ロジック」、`dialectic.md` §2–2.7、§4–5、§8、`model-roster.md` §5、§7、`OVERVIEW.md` §8。

## 4. 人物像とゲームの文脈　注意

探索を好む人と達成速度を重視する人なら、同じ「目的地を常時表示する」仕様から、寄り道の発見と迷走時間という別の確認事項を引き出せる。価値軸は評価項目の選択に、人生脚本は確認・保留・譲歩の仕方に効かせたい。ゲームの型は比較の背景に使えるが、実際にその作品に備わる機能は個別資料で確かめる必要がある。

Histrio が形成する人物像・人生脚本を正本とし、Di が討論用の短い記述にする分担は妥当。Voluptas 由来の遊び手データ、公開発言由来の代理、架空の脚本では由来が異なる。Di のプールにある属性を Histrio の人物へ結び付けた根拠と版を記録し、対応が不明なら脚本行を省く。Ludus の複合ジャンルはペーパー確認時に訂正可能とし、期待から意図的に外した個別仕様を優先する。代理に脚本を混ぜない方針も支持する。

根拠　`spec/feature/flow/persona-pool.md`「責務境界」、`proxy-debate.md` §3–6、人物像・ゲームの型の案 §2–4（`spec/plan/2026-11-23-persona-game-archetype-context.md`）。Histrio の `spec/feature/persona-chat-engine.md` §1・3、`virtual-persona-life-script.md` §1–5、`role-model-engine.md` §2。Ludus の `spec/data/game-template/README.md` §1–2。

## 5. 根拠と誤った前提　重大

声の固定番号で原文の一致は検査できる。さらに「この作品で体験したこと」「類似作からの類推」「仕様に書かれた挙動」「設計者が意図した感情」「未検証の説明」を区別する必要がある。ゲーム別の均等混合は資料の少ない作品に発言機会を与えるが、混合後の割合を対象ゲームの利用者の割合とは読めない。機密時の想定意見に由来を付ける既存規則は、この区別を結論まで保つ先例になる。

撤回の単位は推論とする。一つの声から導いた「協力機能が復帰を促した」を撤回しても、「一緒に遊んだ」という引用は使える。各結論文から論点、存続中の論拠、資料 ID を順に引けるようにし、失効した推論を経由する文を採用対象から外す。これで明示された参照は機械検査できる。正しい ID を添えた意味の飛躍には原文対照が必要で、再生成後も整合しなければ決着表と不足資料だけを表示する。

根拠　`spec/feature/flow/user-voices.md`「流れ」「正直な限界」、`OVERVIEW.md` §5.1–5.4、`proxy-debate.md` §3、7 月再設計の `08-paper-provenance.md`、v2 案 P3・P4・P8・P9。

## 6. 質の測り方　注意

ペーパー #143、同じ三論点、同じ観点で #144 と比較する手順は、既知の欠陥の再発検出に向く。声番号の不一致件数、決着表から落ちた論点数、失効した論拠への参照数は一件でも失敗と判定できる。深さの偶奇と陣営の順序を入れ替え、打ち切りだけで勝者が変わらないことも確認したい。

同一議題の二評価者が 4/5 を付けても、別ジャンルや材料不足時の有用性は測れない。版・ペーパー・声・キャスト・モデル設定を固定して複数回比較し、定義が割れる題、実測が必要な題、価値の両立案があり得る題を含める。版名を隠した結論を作り手に渡し、「次の試行と対象者を特定できたか」「保留の理由を原文まで辿れたか」を記録する。代理の伏せた発言による判別率は人物らしさの補助指標になる。施策が実際に継続率を改善したかは、討論外の観測が必要である。

根拠　v2 案 §1、§5、P10、`spec/feature/flow/proxy-debate.md` §5・8、`OVERVIEW.md` §8。

## 7. v2 とアーキタイプ案の順序　重大

v2 は P2 の未決状態と P1 の終了理由を先に揃え、P4 の固定 ID とともに P3 の決着表を構成する順がよい。深さを 4 から 5 にすると最終発言者が移る。公平性を担保するのは上限で切れた枝をどちらにも加点しない規則である。P5 の定義不一致では両者の定義を併記し、定義を揃えると判断可能になるかも残したい。P7 で批准結果を見せる際は、成立例に加え却下理由も追えると、次の試案につながる。

人物像案は A1 の人物記述、A2 のジャンル背景、A3 の脚本を別々に評価できる構成がよい。受入条件にある「違う人物が選ばれた」に加え、同じ資料・同じ問いで人物だけを替えたとき、遊び手ごとの確認項目が増えたか、架空の体験を観測事実として語っていないかを調べる。決着表と根拠の整合を先に固めると、人物らしい誤説明が増えた場合にも検出できる。

根拠　v2 案 §2–5、人物像・ゲームの型の案 §2.2–4。

## 8. 代替設計　注意

資料不足で判断が止まりやすい題では、各論点について先に「問い・判定基準・既知の事実・欠けている材料」の表を作り、異なる説明が残った行だけ小さな賛否の応酬に渡す方式が適する。たとえば「更新頻度が復帰を促すか」は期間別データの不足を一行で示せる。一方、「復帰者向け短縮と探索の楽しさをどう両立するか」には、現行方式で双方の条件を保存する第三案を生成・批准する価値がある。

小議論の独立化には、複数論点が同じ未検証の仮説に依存していることを見落とす欠点がある。最終集計では共通の資料・推論 ID を突合し、行をまたぐ依存を表示する。人の介入点は開始時の問いと判断基準の承認、および終了時にどの不足資料を集めるかの選択に置く。全編の置換に先立ち、同じペーパーで「作り手が選べた次の行動」と一論点当たりの呼び出し数を比較したい。費用削減幅は未測定である。

根拠　`spec/feature/flow/dialectic.md` §2、§3–7、7 月再設計の `06-dialectic-core.md`、`09-paper-gate-debatability.md`、v2 案 P3、§6。

## 設計として直すべきこと（上位 5 件）

1. **重大**　終了理由と未決状態を先に確定し、上限打ち切り・未応答から論破を導けないようにする。
2. **重大**　資料、推論、決着を固定 ID で結び、撤回を最終要約まで伝える。参照と本文の整合を確認できない場合の表示を決める。
3. **重大**　論点ごとに判断基準を固定し、決着に対象者・試せる変更・保留解除に必要な観測を添える。
4. **注意**　人物の価値軸を維持しつつ、論点単位の立場と必須条件を表明できるようにする。型に由来する推測は明示する。
5. **注意**　同一ペーパー回帰に、版を伏せた複数議題の比較を加える。作り手の判断可能性と、そこに要した呼び出し費用を対で測る。

## 残すべき良い判断

- 人が承認した論点を最後まで扱い、両側の根拠が崩れた場合には「結論なし」を許す。都合の悪い問いも記録に残る。
- 反論の対象を一件に絞り、生成・折衷判定・両側批准を分ける。採用した第三案が何を保存したのかを後から問える。
- ペーパーで出所を明らかにし、代理には原文との帰属検査を課す。人物の発言、ゲームの仕様、仮説を区別する既存の足場として使える。
