# 論述パターン — あえて不完全な人間として議論に参加させる

## 0. 依頼

neco (2026-11-23):「その他論述のパターンを持たせる。例えば Histrio には人生脚本のパターンを使って、あえて不完全な人間として
議論に参加させる」。

今の議論者は全員が同じ「完全な論者」として振る舞う (同じ指示文・同じ前提ルール・深掘りとゲートで形を整えられる)。
実際の議論では、人は癖を持って論じ、言い過ぎ・前例への固執・決定の先送りなどをする。その癖が議論の対立軸と、
作り手が見落としやすい視点 (保守的な遊び手・リスクを気にする人など) を生む。

## 1. 方針: 不完全さは「論じ方の癖」として出し、形は崩さない

- 癖は **何を言うか・どれだけ強く言うか・いつ認めるか** に出す。論拠の形 (データ・論拠) は崩さない。
  形を崩すと深掘り (論拠の不足) とゲートで消えるだけで、議論に残らない。
- 癖のある主張 (確度の言い過ぎ・前例への偏り・例外を挙げない など) は **相手の反論の的** になる。トゥールミンの
  突く先 (限定 = 範囲・確度 / 例外条件 / 裏付け) がそのまま癖を突く道具になる。不完全さが議論で見える形になる。
- 人を否定・攻撃する発言はしない (Histrio §4.3 の安全規則: get-rid-of は常に建設的反論で出す)。

## 2. パターンの 2 軸

### 2.1 軸 A — 人生脚本パターン (反応の癖。正本は Histrio の `script_patterns`)

Histrio の 6 種を、論拠の応酬での振る舞いへ写す (健全側を既定、押されたときはストレス側)。

| パターン | 定立での癖 | 応酬での癖 | 押されたとき (ストレス側) | 突かれやすい所 |
|---|---|---|---|---|
| `until` (〜するまでは) | 確度を「条件つきで」に下げ、前提条件を例外に並べる | 前提が揃っていない点を突く (限定) | 「まだ早い」で保留し、認めも反論もしない | 保留の連発 (決着しない) |
| `after` (〜した後で) | 成功例の後の揺り戻しを例外に挙げる | 決着しかけた論点に後からリスクを足す (例外条件) | 決まったことを蒸し返す | 後出しの例外の裏付け |
| `never` (決して) | 現状維持の側に立ち、確度を強く言い切る | 新案のデータを疑う | 認めない (concede を避ける) | 確度の言い過ぎ (限定) |
| `always` (いつも) | 帰納 (前例) に偏り、裏付けを前例で埋める | 他のゲームの例で押す | 前例が違うと言われても同じ前例を繰り返す | 前例と今回の仕様が同じか (データ・裏付け) |
| `almost` (もう少しで) | 根拠を足し続ける | 結論間際に追加の検討を差し込む | 「あと一点だけ」で決着を延ばす | 論点のずれ (前提ルールの topic_shift に近づく) |
| `open_ended` (結末のない) | アブダクション (作りたい体験から) に寄る | 決着後に「次に何をするか」を問う | 結論を出さずに次の論点へ行こうとする | 主張の範囲が広すぎる (限定) |

- エゴグラム等の従属項は口調だけに使う (Histrio §1 と同じ)。立場 (賛否) は変えない。
- OK牧場の象限は、押されたとき (論拠が崩れた・認めさせられた) の揺れ先に使う。司会 (進行役) は場を自他肯定へ戻す
  定型の一言 (要約・相互承認) を挟む (Histrio §5)。

### 2.2 軸 B — 論じ方の好み (論拠の種類の偏り)

演繹 / 帰納 / アブダクションのどれに寄るか (§2.5 の 3 種類)。軸 A と独立に持たせ、同じ陣営に同じ偏りの人を並べない。
遊び手の型 (アーキタイプ A1) とは別物 (何を好むか ≠ どう論じるか)。

## 3. 仕組み

1. **カタログ**: パターンごとに「定立の癖 / 応酬の癖 / ストレス側 / 揺れ先の象限」を設定データで持つ (上の表)。
   正本は Histrio の `script_patterns` (版付き)。Histrio が動くまでは、Histrio の設計書から作った版付きのデータファイル
   (`data/argument-patterns.json`) を Di が読む (アーキタイプ設計の Ludus と同じ扱い)。
2. **割り当て**: 議論者ごとに軸 A を 1 つ、軸 B を 1 つ。既定は seed からの決定的な割り当て (同じ議論は同じ割り当て)。
   ペーパーで人が指定もできる。代理議論 (本人の発言に縛る) には割り当てない。
3. **発言への載せ方**: 定立・応酬の prompt の人物の欄に「あなたの論じ方の癖」を 1〜2 行 (A1 の人物像の行の隣)。
   押されたかどうかは応酬の状態 (自分の根拠が崩れた・認めた) からコードで決め、ストレス側の行に切り替える。
   LLM の呼び出しは増えない。
4. **露出**: 癖の名前は議論の中で名乗らない。決着表・記録 (`flow_session_persona`) には割り当てたパターンを残す
   (作り手が「この結論は never の人が押し切った」と読めるように)。
5. **測り方**: 代理議論の判別評価を流用し、伏せた発言からパターンを当てられるか (癖が発言に出ているか) を測る。
   癖を入れた議論と入れない議論で、決着表の「次に確かめること」の数と多様さを比べる。

## 4. トークン

prompt に 1〜2 行 (約 100 トークン) 増えるだけで、呼び出しは増えない。押されたときの切り替えはコードで決める。

## 5. 人間判断 (2026-11-23 neco「全部推奨どおり」で確定)

| # | 事項 | 推奨 | 理由 |
|---|---|---|---|
| P1 | 不完全さの出し方 | **論じ方の癖 (言い過ぎ・前例への固執・保留など) で出し、論拠の形は崩さない** | 形を崩すと深掘りとゲートで消える。癖は相手の反論の的として議論に残る |
| P2 | カタログの置き場所 | 議論者テンプレートのプロフィールと ID・版が一致する `GET /v1/script-patterns?namespace=di` の行を優先する。カタログだけが取得できない場合は同じ ID の Di の写しを使う | Histrio が未設定、接続失敗、未登録、形式不正などの場合は、議論開始時の脚本と出所 `di` を維持する。軸 B は Di が扱う |

neco (2026-11-24)「Di の議論者はワンオフで作られた人格なので人格として扱うには不適切」「議論者のテンプレートを用意してけばいいんじゃないかな」。使い捨てのプール参加者はテンプレートで Histrio とつなぐ。Steam 代理は [人物パック契約](../interface/proxy-persona-pack.md) の Histrio ID があるときだけ照会する。実装参照は `actio:d4ddf2a8-8c2b-40b2-b8b2-0e722893d224`。
| P3 | 割り当て方 | **seed から決定的に割り当て、ペーパーで人が上書きできる。同じ陣営に同じパターンを並べない** | 再現できる・比較できる。対立軸が偏らない |

## 6. 実装 (2026-11-23)

| 項目 | 置き場所 |
|---|---|
| Di の写し (版 `di-2026-11-23.1`) | `data/argument-patterns.json`。C++ は同じ内容の組み込み版を持ち、`<repo_root>/data/argument-patterns.json` があればそちらを読む (`argument_pattern_catalog.{hpp,cpp}`)。両者の一致はテストで確かめる |
| 揺れ先の象限 | Histrio §4.1 の例 (`until` → `I-U+`、`always` → `I+U-`) 以外は Di の仮置き (`after`・`almost` → `I-U+`、`never` → `I+U-`、`open_ended` → `I+U+`)。Histrio の `script_patterns` が版を出したら差し替える |
| 割り当て | `assign_argument_patterns` (`argument_pattern.{hpp,cpp}`)。対象は進行役・代理以外の発言者。seed は議題 (同じ議題・同じキャストなら同じ割り当て)。陣営ごとに seed から決まる位置から未使用のものを順に取る (軸 B は 3 種類なので 4 人目から重なる) |
| 人の上書き | ペーパー本文の `# 論じ方の癖` 節。行は `- 名前: パターン / 論じ方` (id か表示名、どちらか一方でも可)。カタログに無い値は捨てる。上書きは重なりの制約より優先 |
| prompt | 定立は「定立の癖」、応酬は「応酬の癖」の行と論じ方の好みの行を、人物像 (A1) の行の後に載せる |
| 押されたとき | 応酬で発言者の陣営の定立の論拠が 1 つでも崩れた (challenged / conceded) 論点では、ストレス側の行に切り替える (`is_pressed_in_exchange`)。論点が変われば戻る。LLM の呼び出しは増えない |
| 記録 | `flow_session_persona.script_pattern` / `reasoning_style` / `pattern_catalog_version` (migration `2026-11-23-session-persona-argument-pattern`)。ログに `論述パターン (版): 名前=パターン/論じ方` |
| 設定 | `flow.dialectic.argumentPatterns` (env `DISCUTERE_FLOW_DIALECTIC_ARGUMENT_PATTERNS`、既定 true) |
