# 議論エンジンの設計評価 — 統合

## 0. 結論

総合 **2〜3 / 5** (3 者)。論証を状態として持ちコードで決着させる骨格・折衷ゲート・敵対的批准・
「結論なし」を正当な出力にした判断は 3 者とも「残すべき」と評価した。一方で次の 3 点は 3 者一致で重大:

1. **決着の土台が壊れている** — 打ち切り・応答障害が勝敗に化け、崩れた根拠が止揚と結論に入る。
   → 本 PR (v2 実装、`2026-11-23-dialectic-v2-implementation-plan.md` V0〜V8) で直した。
2. **出力が作り手の判断に使えない** — 結論が「手続きの結果」で、何を試すか・何が分かるまで保留するか・
   決着に要る材料が書かれていない。→ 本 PR で決着表 (残った / 未決 / 崩れた根拠・未討議・次に確かめること) までは入れた。
   「決着カード / 意思決定シート」への再設計は R1 (人間判断)。
3. **質を測る仕組みが無い** — 同じ議題 1 本の再実行と AI レビューの点数に頼っている。
   → 記録の整合の自動検査・固定議題セット・複数回の一致率が要る (R3)。

## 2. 代わりの設計 (2 者が提案)

- **Neon 代替案 A — 設計レビュー型**: 賛否を固定せず、遊び手の型 3〜4 人が独立に評価 → 割れた点だけ集中応酬 →
  統合案 + 敵対的リスクチェック → 意思決定シート (合意 / 条件付き推奨 / 未解消のリスク / 次の検証 / 参照した声)。
- **Fable 案 A — 論点ごとの小議論 + 独立審査**: 論点 = 命題 + 定義 + 判定基準 → 定立 → 型判定を前倒し →
  応酬は固定 2 手 → 論拠ごとに独立の審査役 (今の投票の枠を付け替え) が「残る / 弱まった / 崩れた」を多数決 →
  コードが集計し決着カードを出す。止揚は「未検証の提案」。
- 共通: 状態をコードで持つ・敵対的批准・結論なしの許容・出所の明示は残す。勝敗を「反論の形が残ったか」で決めない。

## 3. 人間判断

| # | 事項 | 推奨 | 理由 |
|---|---|---|---|
| R1 | 決着方式と出力を組み替えるか (Fable 案 A / Neon 代替案 A / 今の方式 + v2) | **今の方式 + v2 を基準として 1 回実測し、同じ議題で Fable 案 A を試作して比べる** | v2 で決着の土台は直したので、まず v2 の結論が作り手に使えるかを見る。案 A は今の投票と審査の枠を流用でき試作が安い。比べずに組み替えると何が効いたか分からない |
| R2 | 意見役の席をどうするか | **dialectic では意見役を作らず、全員を賛否の議論者にする** (モデル編成の先頭が発言する席に当たる) | 今は意見役に価値軸を生成しても発言経路が無く、編成の上位モデルが空席になっている |
| R3 | 質の測り方 | **固定議題セット (仕込み入り 5 本程度) × 複数回実行で、記録の整合の自動検査・決着の一致率・呼び出し回数を測る** | 3 者とも AI レビューの点数を受入にしないよう求めた。実 LLM を回すので実行の許可が要る |
