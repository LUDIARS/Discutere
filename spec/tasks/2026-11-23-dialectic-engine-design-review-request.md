# 議論エンジンの設計評価レビュー依頼

## 目的

Discutere (Di) の議論エンジンの**設計そのもの**を評価する。実装が仕様どおりかではなく、
「この設計は、議論エンジンの目的を果たす設計として妥当か。もっと良い設計はあるか」を見る。

議論エンジンの目的 (仕様から読み取って、まず自分の言葉で書くこと): ゲームの仕様・体験について、複数の AI 人物が
プレイヤーの声とゲームの資料を根拠に議論し、作り手が使える結論 (改善の方向・決着しない点) を出す。

## 観点 (すべてについて書く)

1. **目的との適合**: 論証モデル (主張・データ・論拠・限定、論拠の応酬、止揚 / 論破 / 結論なし) は、ゲームの改善を考える議論に合っているか。
   作り手が結論を読んで次の手を決められる出力になっているか。
2. **役割と進行の構造**: 進行役・賛成・反対・意見役の分け方、賛否をセッション開始時に固定すること、論点分解、収束の決め方。
3. **評価・判定の仕組み**: 投票、判定 LLM (前提ルール・認める・向き・型分類)、折衷ゲート、批准、事実照会。
   それぞれ何を保証するための仕組みか、その保証に見合うか、無くてよいもの・足りないもの。トークン (LLM 呼び出し) の使い方として妥当か。
4. **人物像と文脈**: 人物 (価値軸・遊び手のタイプ・人生脚本) とゲームの型 (ジャンルの型) をどう持ち、発言にどう効かせるべきか。
   人物像の正本を Histrio に置く方針、アーキタイプ設計案の評価。
5. **根拠の扱い**: プレイヤーの声 (外部の声)・ゲームの資料・推測の区別、誤った前提や崩れた論拠が結論に入らない設計になっているか。
6. **測り方**: 議論の質をどう測る設計か (評価指標・再テスト・版の比較)。測れない部分。
7. **v2 改善設計とアーキタイプ設計案**: 方向として正しいか、設計の穴、優先順位。
8. **代わりの設計**: 根本的に別の組み方 (例: 論点ごとの独立した小議論、決定的な集計中心、人間の介入点の置き方 など) で明らかに良いものがあれば、
   今の設計と比べて書く。
