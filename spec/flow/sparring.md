# 壁打ちフロー (Sparring)

> 状態: ドラフト (2026-06-13)。共通仕様は [OVERVIEW.md](./OVERVIEW.md)。

**ユーザターン起点**で議論を始め、ユーザの不定期な発話に対して議論を続ける対話フロー。
議論フローと違い**ラウンド数・ターン数の固定制限を設けない** (暴走ガードの上限は設ける)。
ユーザのコマンド発話でラウンド締め・終了する。

> **入口**: 壁打ちは**テーマ投稿時に議論タイプ「壁打ち」を選択**して入る (OVERVIEW §9)。
> 発話内容からの自動判定ではない。WebUI は選択 UI、Discord はフォーラムの適用タグで指定。

## 進行

```
ユーザ発話 (起点)
   ▼
ルールエンジンによる議論 (応答)
   ▼
ユーザ発話 (不定期・任意のタイミング) ──┐
   ▼                                  │ 繰り返し (上限まで)
ルールエンジンによる議論 (応答) ────────┘
   │
   ├ ユーザ「まとめて」 → そのラウンドを終了 (ファシリテーターがまとめ)
   └ ユーザ「おわり」   → 議論を終了し、まとめに入る
```

- **起点**: ユーザターンから議論開始。
- **発話**: ユーザは**不定期の発話**でよい。各ユーザ発話に対し、**ルールエンジンによる
  議論を継続**する (現 `respond-to-human` / `human-*` の人間優先即応を流用)。
- **制限**: ラウンド数・ターン数の固定制限なし。ただし**上限を設ける** (暴走ガード。
  設定値、例 `flow.sparringMaxTurns`)。

## 終了コマンド

| ユーザ発話 | 動作 |
|---|---|
| **「まとめて」** | そのラウンドを終了する (ファシリテーターがラウンドまとめ → 続行可能) |
| **「おわり」** | 議論内容を終了して**まとめに入る** (= フロー終了) |

> コマンド検出の実装は分類器 (`classifier`) / 文字列一致のどちらに寄せるか、ゆらぎ
> (「まとめてください」等) の許容範囲は実装時に確定。

## 既存資産との対応

- Web チャット議論 (現 `spec/feature/web-chat.md`、`scene=web:<room>`) の 1 対 1
  ポーリング対話が起点として近い → 流用候補。
- 人間優先即応は現 persona-engine の `human-facilitator` / `respond-to-human` ルール。
