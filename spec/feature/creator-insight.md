# つくり手インサイト

2026-11-13 指示: Slack / Discord のログ、ポートフォリオ、コードの書き方から、人生脚本・性格・プレイタイプを分析できるようにする。
人生脚本はアンケート式にする。まず LLM スキルとして導入し、集計はロジックで行う（ツールは必要になった時点で作る）。日本に特化する。

入口は `skills/creator-insight/SKILL.md`。本人の振り返りと、本人との対話の準備に使う。

## 境界と受入条件

- DI-CI-01: エージェントが読んで実行するスキルとして提供する。サーバ（`native/`）の機能、slash command、HTTP の経路、DB のテーブルを足さない。
- DI-CI-02: 本人の同意と目的の確認が無い場合は実行しない。採用・選考・評価・診断・監視には使わない。
- DI-CI-03: LLM が読むのは、特徴カード（仮名化済みの集計）と上限つきの引用だけ。生のログ・コードを文脈に入れない。アンケートの採点に LLM を使わない。
- DI-CI-04: 分析結果を KG・SQLite・ディスカッションペーパー・ペルソナプールへ書き込まない。Discutere の DB から個人別のログを作らない。
- DI-CI-05: 出力は、根拠 ID と確度を付けた仮説とする。根拠不足は「データ不足」と書き、低い値と区別する。神経症傾向と、要配慮個人情報にあたる事項は出さない。
- DI-CI-06: 集計ツールは `scripts/creator-insight/` に必要になった時点で作り、架空データのテストを `tests/creator-insight/` に置く。仮名化を最初の段で行い、本人以外の本文を捨てる。
- DI-CI-07: 前提は日本語話者と日本の制作現場。比較は同じ集団の中の相対位置だけで行い、性別・年齢・出身などの属性を推定しない。

## 3つの分析

| 分析 | 正とするもの | 補助 |
|---|---|---|
| 人生脚本 | 本人が答えるアンケート（ドライバー、プロセス脚本、基本的構え） | ログの行動指標との照合 |
| 性格 | ログ・コード・ポートフォリオの行動指標（外向性、協調性、勤勉性、開放性） | 組織が持つ既存尺度の自己申告 |
| プレイタイプ | Voluptas と共有する15軸。遊び手と作り手を分ける | ゲームについての発言、作ったもの |

分析の要点は `skills/creator-insight/references/` の各文書が正本。

## データの扱い

| データ | 置き場所 | 保持 |
|---|---|---|
| エクスポートしたログ、中間ファイル | リポジトリの外の作業ディレクトリ | 分析の終了時に削除 |
| 特徴カード | 同上 | 本人への返却後に削除。本人が望む場合は本人に渡す |
| 対話用メモ | 本人に返す | 本人が管理する |
| 仮名化の鍵 | Ex Vault（`DISCUTERE_CREATOR_INSIGHT_HMAC_KEY`） | 鍵の更新で過去の仮名 ID は照合できなくなる |

同意が撤回されたら、すべての作業ファイルをただちに削除する。

## 検証

今回の変更はスキル文書・設問データ・架空の例だけで、実行コードを含まない。

- 設問は51問（ドライバー20、プロセス脚本18、基本的構え8、強制選択5）。ID の重複が無いこと、強制選択の各場面が5つのドライバーを1つずつ含むことを確認する。
- 採点キーは、架空の回答 `examples/life-script-answers.example.json` を手順どおりに採点し、`examples/feature-card.example.json` の `questionnaire.lifeScript` と一致することを確認する。
- 採点ツールを作る変更では、同じ回答例を受入テストに使う。
