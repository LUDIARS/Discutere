# 議論フロー (Discussion)

> 状態: ドラフト (2026-06-13)。**2026-07-02 改訂**: Fable セッションレビューの指摘を反映
> (stance セッション固定 / シャッフル輪番 / レンズ投票 / 結論入力拡充 / 収束条件の AND 化)。
> 改訂の実装設計は [`spec/plan/20260702_respec_from_fable/`](../../plan/20260702_respec_from_fable/README.md)。
> 議論の「中身」(論証状態・止揚・収束の本体) は **弁証法エンジン**
> [dialectic.md](./dialectic.md) に規定し、本書の 9 ステップは rounds エンジン
> (`flow.engine="rounds"`、既定) の骨格として残す。
> 共通仕様 (ユビキタス言語 / 設定 / タグ / ディスカッションペーパー / RAG /
> コストログ) は [OVERVIEW.md](./OVERVIEW.md) を参照。

テーマに対し、複数のロール (賛成派 / 反対派 / 意見屋) が複数ラウンドにわたって意見を
ぶつけ、ファシリテーターが各ラウンドをまとめ、投票で世論を測り、最終的に結論を出す
(出なければ「結論なし」)。

## 全体像

```
テーマ受信 (人間/AI)
   │  + タグ (機密/内部/運用/開発)
   ▼
[2] メカニクス + 感情データ調査
   │   └ 感情データ 0 件 かつ 機密/内部でない → [2-1] YouTube 検索で補完
   ▼
[3] ディスカッションペーパー生成 (ロール×LLM性質で内容可変)
   ▼
┌─ ラウンド (設定: ラウンド数) ───────────────────────────┐
│ [4] ファシリテーターがテーマ出題・ラウンド開始 (ターン数を設定から取得)  │
│ [5] ターン数ぶん 議論プレイヤーに発言要求                              │
│      渡すのは ペルソナ + ディスカッションペーパー + 当ラウンドの意見のみ │
│      └ [5-1] 場合により RAG (ゲーム機能/特定機能の感情検索) を許可      │
│ [6] ラウンド終了 → 投票 (設定人数・中立) + 感情ベクトル評価             │
│ [7] ラウンドの意見をサマライズ + 止揚をまとめ → ペーパーに追記          │
└─────────────────────────────────────────────────────┘
   │  [8] 指定ラウンド数まで継続 (新ラウンドは過去より現ラウンドの意見を優先参照)
   ▼
[9] 結論を出す / 出なければ「結論なし」 / 早期に出たら打ち切り
```

---

## ステップ詳細

### 1. テーマ受信

- 人間 (Discord / Web チャット) または AI (autoSeed 等) からテーマを 1 つ受信する。
- テーマには**タグ**が付く (`機密` `内部` `運用` `開発` ほか。なし可)。
  → タグの効果は [OVERVIEW §3](./OVERVIEW.md#3-タグ-機密--内部--運用--開発)。

### 2. メカニクス + 感情データの調査

- テーマに関連する**ゲームのメカニクス** (Discatier Core の `mechanics` /
  `data/games/<slug>.md`) と**感情データ** (現 `*.sentiment.json` / `affects` /
  感情カスケード `src/crawler/sentiment/cascade.ts`) を集める。

#### 2-1. 感情データが不十分 (0 件) のとき

- 感情データが **0 件** と判断した場合、**YouTube で検索**して補完する。
- ただし **`機密` または `内部` タグが付く場合は行わない** (外部収集禁止、OVERVIEW §3)。
- 実体は YouTube Data API 検索 → コメント収集 → 感情カスケードで極性付与。
  既存の YouTube 取り込み (`task #128` の外部音声インポート / `youtube-comments` skill) を流用。
- **取得量は 1 議論あたり 100〜200 コメントで十分** (1 議論に多量のコメントは要らない)。
  事前学習なしの議論を 1 日に 100 回も回す想定はないので、`search.list` クォータも実用上問題ない。
- **外部取得の前にユーザへ警告を出す** (「感情データが無いので YouTube を検索します」等)。
  外部 API を叩く前に明示する。

### 3. ディスカッションペーパー生成

- (2) の調査結果を元に、エージェントへ配布する**ディスカッションペーパー**を作る。
- フォーマット (記載内容) は **ロール × LLM 性質**で変わる
  → [OVERVIEW §5](./OVERVIEW.md#5-ディスカッションペーパー)。
  - 共通: テーマ + メカニクス + タグ補足 + 前ラウンド結果
  - 意見屋: + ユーザ意見まとめ (YouTube/Steam ランダム抽出)
  - ローカル LLM: ロール問わず + RAG ユーザ意見ランダムチョイス
  - 機密: ユーザ意見の代わりに**想定意見データ**

### 4. ラウンド開始 (ファシリテーター出題)

- ファシリテーターがテーマを出題し、ラウンドを開始する。
- そのラウンドの**ターン数を設定から取得**する (`flow.turnsPerRound`)。
- **(2026-07-02 改訂)** ラウンド 2 以降の出題には**前ラウンドの結果 (サマリ / 止揚 / 世論)**
  を文脈として渡し、「まだ深まっていない論点へ進める出題」をさせる。ラウンドを
  「同じ議論の N 回試行」にしない ([02](../../plan/20260702_respec_from_fable/02-turn-scheduling.md))。

### 5. ターン進行 (発言要求)

- 取得したターン数に従い、**議論プレイヤーそれぞれにターンを回して回答を要求**する。
- 各ターンで発言者に渡すのは **3 つだけ**:
  1. **ペルソナ** (そのプレイヤーの人格 + 賛否スタンス + 価値軸)
  2. **ディスカッションペーパー**
  3. **そのラウンド中の意見** (= 当ラウンドでこれまでに出た発話)
- **(2026-07-02 改訂)** 賛否スタンスは**セッション開始時に固定**する (毎ターン再抽選は廃止。
  人格に一貫した立場を持たせる。[01](../../plan/20260702_respec_from_fable/01-persona-state.md))。
  各ペルソナには開始時に**価値軸** (重視する価値) を 1 回の LLM 呼び出しで生成して注入する。
- **(2026-07-02 改訂)** 発言者割り当ては**シャッフル輪番** (ラウンド開始時に rng シャッフル →
  巡回)。ターン数 ≥ 人数なら全員が最低 1 回発言する。ファシリテーターは開幕ターン専任で
  ターンループには入らない ([02](../../plan/20260702_respec_from_fable/02-turn-scheduling.md))。
  dialectic エンジンでは論証状態に基づく**指名制** (応答権) になる ([dialectic.md](./dialectic.md) §3)。
- 空応答は発話に数えない (現挙動踏襲)。

#### 5-1. ターン中の RAG (条件付き許可)

- 場合により、**ゲーム機能や特定機能の感情の検索** (RAG) をターン中に許可する。
- `機密`/`内部` タグ時は外部の新規収集はしない (既存 KG 内検索に限る)。

### 6. 投票 + 感情ベクトル評価

- ラウンドが終了したら、**設定人数による「投票」**を行う。
  - 投票者は**中立** (ペルソナを注入しない)。テーマに最も的を射た「良い意見」を **1 つ選んで
    リアクション**する。各投票者は 1 票。**得票数 = 世論 = そのラウンドの主要意見**。
  - 投票者数は `flow.voterCount`。
  - **(2026-07-02 改訂)** 同一プロンプト N 連投は N 票の意味を持たない (強相関) ため、
    投票者ごとに**評価レンズ** (論理性 / 根拠 / テーマ適合、`flow.voteLenses[]`) を割り当て、
    **候補提示順を投票者ごとにシャッフル**して位置バイアスを脱相関する。番号回答も受理。
    同点は先着ではなく rng くじ ([03](../../plan/20260702_respec_from_fable/03-vote-lenses.md))。
  - 既存のリアクションスコア機構 (👀 + 人間下駄) は**採らない** (結果整合性のパラドックスを
    起こすため。OVERVIEW §11-b)。専用の中立投票フェーズとして実装する。
- 併せて**意見の感情ベクトル評価**を行う (「感情曲線」という旧表現は破棄)。
  - 各意見の感情ベクトルが、テーマ / 目標 (メカニクスの `intended_affect`) のどのベクトルに
    近いか、ベクトルの**近さ**で適合を判定する。
  - 議論フローではこの評価を補助シグナルとして使う (世論は投票で決まる)。
    **改善フローでは投票でなく機械計算 (design_gap) が世論を決める** ([improvement.md](./improvement.md))。

### 7. ラウンドサマリ + 止揚の追記

- ラウンドの意見を一度**サマライズ**する。
- **止揚 (アウフヘーベン) した意見があればまとめる** (現 `aufhebung_stock` /
  `judgeAndStockAufhebung`)。
- まとめた意見を**ディスカッションペーパーに追記**する (次ラウンドの共通項目になる)。
- **(2026-07-02 注記)** 単発の LLM 判定による止揚検出は「判定者の創作」になりやすい既知の
  構造問題を持つ。本体の解決は dialectic エンジンの**生成 + 敵対的批准** ([dialectic.md](./dialectic.md)
  §4〜§5) で行い、rounds エンジンでは判定 JSON のパース失敗を warn で可視化するに留める。

### 8. 次ラウンドへ (継続条件)

- 議論フローは**指定ラウンド数 (`flow.rounds`) まで進める**。
- 新しいラウンドでは、**過去の意見より現在のラウンドの意見を優先参照**する
  (ディスカッションペーパーの「前ラウンド結果」は要約として持つが、現ラウンド進行中は
  当ラウンドの発話を主文脈にする)。
- これは `prompt-builder` のコンテキスト構築を**当ラウンドスコープ優先**に変更して実現する
  (現状はグローバルに直近発話を入れている)。

### 9. 結論

- **結論を出す**。
  - 出ていない場合は **「結論なし」** とする。
  - 結論が**全ラウンド完走前に出た場合はそこで打ち切る** (早期収束)。
- **(2026-07-02 改訂)** 結論生成には**全ラウンドのサマリ**を渡す (従来の「直近 20 発話 +
  止揚 + 世論」だけでは序盤ラウンドが落ちる)。結論 JSON のパース失敗は 1 回リトライし、
  なお失敗なら `concluded=false` + `【収束(未検証)】` で degrade を明示する
  ([04](../../plan/20260702_respec_from_fable/04-conclusion-convergence.md))。
- **(2026-07-02 改訂)** 早期収束は「止揚 ≥ しきい値」**単独では発火しない** (止揚は
  ラウンドあたり最大 1 件で、実質ラウンド数と等価のため)。「止揚しきい値 **かつ**
  直近ラウンドの投票集中度 (`winnerShare` ≥ `flow.convergeShare`)」の AND とする。
  計測型収束の本体 (未応答反論数 / 新規論点の枯渇) は dialectic エンジン
  ([dialectic.md](./dialectic.md) §6)。
- **まとめは既存の結論ビュー (`src/visualize/conclusions.ts`) に倣って整形**する。

## 現状 Di からの差分 (実装メモ)

| 項目 | 現状 | 本フローでの扱い |
|---|---|---|
| 駆動 | persona-engine (Concordia 由来のルールエンジン) + DiscussionDirector | **新規 FlowDirector** がターン駆動。persona-engine は不使用 (参考材料として残置) |
| ターン割り当て | 輪番 / rule.target | ~~その場生成ペルソナをランダム選択~~ → **シャッフル輪番** (2026-07-02。dialectic では指名制) |
| ロール | 司会/キーマン/意見 + 毎ターン賛否 | ファシリテーター/賛成派/反対派/意見屋。**賛否はセッション固定 + 価値軸** (2026-07-02) |
| メンバー入替 | swapHalf (ラウンド間半数入替) | **廃止** (全メンバーをその場生成するため不要) |
| 配布資料 | prompt-builder が議題+直近発話を都度組立 | **ディスカッションペーパー**として構造化・永続・追記 (新規) |
| 投票 | 👀 リアクションスコア + 人間下駄 | **中立 N 人の明示投票フェーズ** (新規 `flow.voterCount`) |
| 感情データ補完 | URL 貼付 crawl (手動) | テーマ起点の **YouTube 自動検索** (0 件時・タグ制限・100〜200件・事前警告) |
| タグ | フォーラムタグ (方向のみ) | **機密度+観点タグ** (収集可否+補足、新規) |
| コスト | usage 戻り値のみ | **transcript_log + 発話別コストログ永続化** (新規、OVERVIEW §8) |

## 失敗時 (OVERVIEW §10)

- ターンの LLM 失敗 / YouTube 取得失敗 / 投票失敗 / 要約失敗は、**エラーログ出力 + 発話への
  エラー提示**で扱う (握り潰さない)。空応答とエラーは区別する。
