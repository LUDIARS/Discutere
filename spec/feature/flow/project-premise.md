# 議論タイプのプロジェクト前提

仕様ID: DI-FLOW-PROJECT-PREMISE

2026-10-08 neco 指示: 「企画/議論」はプロジェクトなし、「改善/議論」はプロジェクトありを前提とする。

| 選択肢 | 内部値 | 前提 |
|---|---|---|
| 企画/議論 | discussion | 既存プロジェクトなし。目的・アイデア・比較案から検討する。対象名は不要。 |
| 改善/議論 | improvement | 既存プロジェクトあり。対象・現状・課題・制約を踏まえ、変更案を比較する。 |

プロジェクトとは議論対象のゲーム・サービス等を指す。リポジトリや管理サービスへの登録を新たな必須条件にはしない。

- Discord の選択メニューと Web の選択肢に名称・前提を表示する。旧ラベル「議論」「改善」と保存済み内部値は互換性を保つ。
- 「改善/議論」が短い別名「議論」に誤分類されないよう、具体的な別名を優先する。
- Web の企画はタイトル未定でも開始・下書き編集・再開できる。改善の固定フォームは対象名を必須とする。
- 企画テーマを既存ゲーム名と解釈してメカニクスを自動補完しない。入力された企画案・参考資料は利用できる。
- 草案の理解確認・議論適性評価および実際の議論プロンプトにモードの前提を渡す。改善の不明な現状は質問し、企画の未定仕様を既成事実にしない。
- 既存の外部の声は参考事例として扱う。実ユーザーの声と企画上の仮説を混同しない。

実装: `project-premise.ts` / `dispatch.ts` / `paper-review.ts` / `flow-setup.ts` と Discord・Web の入口。
検証: ラベル解決とタイトル未定の草案に回帰ケースを追加。session 自身のテスト実行・実Discord操作は別途実行許可に従う。
