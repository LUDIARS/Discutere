# 代理議論 (代理戦争AI) — 設計

> 状態: canonical (2026-10-23)。設計の根拠は `spec/plan/2026-10-23-proxy-war-ai-review.md`
> (Fable 案 / Astra 案の統合レビュー、U1〜U5 は neco が「すべて推奨どおり」で確定)。

## 0. 何をするか

公開レビューの書き手 (仮名の話者) の発言から作った人物像を、その人の **AI の代理** として演じさせ、
代理 2 人を既存の dialectic エンジンで議論させる。目的は「この仕様を、こういう好みの人とああいう好みの人なら
どう評価するか」を本人の発言に縛って見ること。**本人の再現・本人の意思の代行ではない。**

- 人物像は微調整 (FT) ではなく in-context で渡す。数値ベクトルはそのまま渡さず、
  言語化 + ジャンル別の望む/不満 + 本人の発言の原文 + 主張と根拠の対応表 (立場カード) の「束」にする。
- 人物像の形成と正本は Histrio の役割 (§6)。Histrio に形成層ができるまでは Di の `npm run proxy:form`
  が同じ契約のパックを作る仮置き (統合レビュー U1)。Di は契約を受け取って議論させる側に留まる。

## 1. 起動

- 観点タグ **「代理」** を付けた議論/改善で、議題に `代理: 論者#xxxxxx, 論者#yyyyyy` を書く
  (任意で `ジャンル: <id>`。2 人に共通するジャンルが 1 つなら省略可)。
  Discord はフォーラムタグ「代理」(ClientReady で自動用意) + スレッド名/starter、Web は議題欄とタグ。
- `flow.proxy.enabled=false` (既定) / `機密`・`内部` タグ / 指定が無い・人物像が使えない ときは
  **ProxyRequestError で止める** (黙って通常議論にしない)。
- 代理議論は `flow.engine` に依らず dialectic エンジンで回る (`dispatch.ts` → `proxy/resolve.ts`)。

## 2. キャストと進行 (`proxy/cast.ts` / `dialectic/driver.ts`)

- 進行役 1 人 + 代理 2 人。代理の露出名は `論者#xxxxxx (賛成派/AI代理)`。欠員を架空の人物で埋めない。
- 代理には価値軸・核主張を生成しない (本人の発言に無い主張を作らない)。進行役だけ persona-setup を通す。
- キャストに出せるのは: 失効していない / 期限内 / confidence が low でない / 評価が failed でない
  (`flow.proxy.requireEvalPassed=true` なら passed のみ)。
- 冒頭の進行文で「論者は公開レビューから作った AI の代理で、本人の発言・同意ではない」と伝える。
- **立場は論点ごとに本人のデータから決める** (`proxy/stance.ts`、判定 LLM・既定 judgeModel)。
  賛成と反対に分かれた論点だけ定立 → 論拠の応酬 → 結論へ進む。両方同じ側 / どちらとも言えない
  論点は反対役を作らず「対立していない」理由付きで結論なしにする。

## 3. 帰属 (`proxy/attribution.ts`)

代理は論拠ごとに本人の発言との関係を申告する:
`sourceQuote` (引用) / `groundedParaphrase` (根拠付き言い換え) / `simulationInference` (推測) / `unknown`。

- 引用・言い換えは、引いた `[E番号]` がすべて束にあること (引用は「」内が原文に含まれること) をコードで検査する。
- 定立の論拠が通らなければ **推測に落とす** (定立は捨てない)。応酬の反論が通らなければ **問いに格下げ**して
  論拠に数えず、進行役が理由を伝える (`unsupported_attribution` / `quote_mismatch`)。検査できない状態を ok にしない。
- 露出文には `[E1,E3]` (本人の発言に基づく) / `（推測）` / `（材料不足）` を付け、
  `flow_utterance.claim_kind` / `evidence_ids_json` に残す。

## 4. 人物パックと束

- 契約: `spec/interface/proxy-persona-pack.md` (v1)。取込は `npm run proxy:import -- --input <jsonl>`
  (`flow_proxy_profile`、1 話者 × 1 ジャンル。flow_persona とは分け、通常議論の憑依候補に混ぜない)。
- 束 (`proxy/bundle.ts`): 既定 3,500 トークン (`flow.proxy.budgetTokens`)、上限 10,000 (`maxBudgetTokens`、U4)。
  予算を超えたら議題と関係の薄い発言から落とし、落とした発言だけを根拠にした立場カードも落とす。
  1 件も載らなければ代理に出さない。数値ベクトルは載せない。
- 1 回の呼び出しに載るのは発話する代理 1 人分の束だけ (相手の主張は既存の定立ダイジェストで見える)。
- 形成 (仮置き、`npm run proxy:form`): steam-persona 等の ExternalUtterance JSONL + ジャンル辞書
  (`data/proxy/genres.example.json` の形) から決定的に作る。LLM 不使用 (U2)。仮名は
  HMAC (`DISCUTERE_PROXY_SPEAKER_HMAC_KEY`、Ex Vault)。本文のリンク・@ハンドルは伏せる。
  4 本以上ゲームがある人は 1/4 のゲームを評価用に伏せ (`heldOut`)、その発言は `--heldout-out` の評価専用ファイルにだけ出す。

## 5. 本人らしさの評価 (`npm run eval:proxy`)

| 指標 | 測り方 | 合格 |
|---|---|---|
| 判別 (必須) | 伏せた発言が 2 人のどちらのものか (本人の位置は交互)。相手は同じジャンルの束にできる人物。1 人あたり最大 12 件 (`--max-texts`) を等間隔に選ぶ | ≥ 0.75。伏せた発言 8 件未満は未評価 |
| 推薦予測 (参考) | 伏せたゲームを本人が勧めたかを束だけで当てる (`--recommend` のときだけ) | 合否に使わない。多数派ベースラインとの差を表示する |
| 根拠付き率 | 代理議論の発話のうち本人の発言に根拠を持つ割合 (`--session`) | ≥ 0.80 (測ったとき) |
| 誤帰属率 | 本人の発言と申告した発話を判定 LLM が「支えていない」とした割合 | ≤ 0.05 (測ったとき) |

`--write` で `flow_proxy_profile.eval_status` に passed / failed / unevaluated を書く。
「分からない」・LLM 障害は正解に数えない (甘くしない)。評価用の発言は形成・束・議論に入れない。
束にできない人物 (confidence=low) は代理に出ないので LLM を呼ばず未評価にする。

推薦予測を必須から外した理由 (2026-10-24 実測): Steam の公開レビュー 198 人分の action ジャンルで、材料が十分な
3 人 × 伏せたゲーム 36 本を測ると、多数派ベースライン 25/36 に対し、束から yes/no を必ず選ばせて 15/36、
勧めたゲーム一覧を足しても 17/36 だった (選択肢に「分からない」があるとほぼ全部「分からない」)。推薦可否は
本人の好みよりゲーム自体の出来で決まる部分が大きく、束の材料では当てられない。本人らしさは判別で測る。

## 6. 責務境界 (Voluptas ↔ Histrio ↔ Di)

| | Voluptas | Histrio | Discutere |
|---|---|---|---|
| 材料 | 同意済み本人のアンケート・プレイ記録 | 公開発言 (取得はクローラ層から受け取る) | 受け取った人物パック |
| 人物像の形成・正本 | 本人の人物像 | 公開発言由来の人物像 (契約 v1) | しない (束の言語化と予算クランプのみ) |
| 生の外部 ID | — | 内部だけで持つ | 持たない (仮名キーのみ) |
| 議論・帰属検査・評価 | — | — | 持つ |

- persona-pool.md の「Di に回答からのペルソナ生成を置かない」は維持する。`proxy:form` は Histrio へ移すまでの
  スクリプト (常駐機能にしない)。
- 生成した発話・観客の反応で本人の人物像を書き換えない (正本の汚染防止)。

## 7. 個人データ

- 対象は公開レビューの仮名話者に限る。Discord の利用者・実名の人・Cc の会話は材料にしない (U5)。
- Di には出典 URL を渡さない (U3)。引用の本文と revision は渡す (Di が引用を検査できるように)。
- 代理議論の結果を外部公開 (GLAB 等) しない (U5)。露出は「代理議論」「AI代理」の名前で行う。

## 8. 非目標・正直な限界

- 本人の将来の行動・未発言の意見の正解は分からない。測れるのは観測された推薦可否と発言の範囲。
- 20D は語彙由来の感情の粗い要約で、本人の価値基準そのものではない。望む/不満は話題にした観点の頻度で決める。
- FT より速く正確かは、この評価の結果で判断する (統合レビュー §1)。
